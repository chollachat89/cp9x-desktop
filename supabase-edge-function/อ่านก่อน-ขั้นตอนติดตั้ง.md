# อัปเดตรอบนี้ (v1.0.6) — ขั้นตอนติดตั้งฝั่งเซิร์ฟเวอร์

โปรเจกต์นี้ใช้ Electron (แอปหน้าเว็บ) คู่กับ Supabase Edge Function เป็นเซิร์ฟเวอร์หลังบ้าน
โฟลเดอร์นี้คือไฟล์ที่ต้องเอาไป **วางบน Supabase Dashboard เอง** — เครื่องมือ Cowork ที่ผมใช้อยู่เชื่อมกับบัญชี Supabase คนละบัญชีกับที่ดูแลฐานข้อมูลจริงของ CP9X จึงแก้ให้จากตรงนี้อัตโนมัติไม่ได้ ต้องมีคนที่มีสิทธิ์เข้า Dashboard ของโปรเจกต์ `hefnjozijflnhdunmewl` ทำขั้นตอนด้านล่างนี้

ถ้าคุณไม่ใช่คนดูแล Supabase ให้ส่งไฟล์ `index.ts` ในโฟลเดอร์นี้ พร้อมเอกสารนี้ให้คนที่ดูแลอยู่แทน

**หมายเหตุ:** รอบนี้ไม่มี SQL ใหม่ต้องรัน (ไม่มีการแก้โครงสร้างฐานข้อมูล) — ถ้ายังไม่เคยรัน `add-unique-constraints.sql` จากรอบก่อนหน้า ให้รันตามเอกสารเดิมก่อน (ดูท้ายไฟล์นี้)

---

## ขั้นตอนอัปเดตโค้ด Edge Function

1. เข้า https://supabase.com/dashboard/project/hefnjozijflnhdunmewl/functions/app-api
2. กด **Edit function** (หรือปุ่มแก้ไขโค้ด)
3. เปิดไฟล์ `index.ts` ในโฟลเดอร์นี้ คัดลอกเนื้อหาทั้งหมด
4. **ลบโค้ดเดิมทั้งหมดในหน้าแก้ไขของ Supabase แล้ววางโค้ดใหม่แทนทั้งไฟล์**
5. กด **Deploy** / **Save and Deploy**
6. รอสัก 10–20 วินาทีให้ deploy เสร็จ

## นี่คือการเปลี่ยนแปลงอะไรบ้าง (รอบนี้)

### 1. สถานะ "พักงาน" ในรายงานสถานะดำเนินการ
งานที่กำลังพักอยู่ (ยังไม่ได้กด "กลับมาทำงาน") จะขึ้นสถานะเป็น **"พักงาน"** ในหน้ารายงานสถานะดำเนินการทันที แทนที่จะค้างเป็น "รอดำเนินการ" เหมือนเดิม (ลำดับความสำคัญของสถานะ: เสร็จสิ้น > ส่งมอบงาน > ปิดงานแล้ว > พักงาน > รอดำเนินการ) — ฝั่งแอปมีช่องแสดง/ตัวกรอง/การ์ดนับจำนวนสถานะนี้เตรียมไว้อยู่แล้ว ไม่ต้องทำอะไรเพิ่มฝั่งแอป

### 2. จัดการคอลัมน์ในตารางรายงานสถานะดำเนินการ
เพิ่มปุ่ม "จัดการคอลัมน์" ที่หน้ารายงานสถานะ ให้ซ่อน/แสดงคอลัมน์ได้เหมือนตารางวางบิล (จำค่าที่เลือกไว้ในเครื่อง ไม่ต้องตั้งใหม่ทุกครั้ง) — เป็นการเปลี่ยนแปลงฝั่งแอปล้วนๆ ไม่เกี่ยวกับ `index.ts`

### 3. แก้ขั้นตอนบันทึกรอบบิล — แยกเป็น "ดูตัวอย่าง" กับ "ยืนยันบันทึก"
เดิมกดปุ่มเดียว ("จับคู่ข้อมูลเปิดงาน-ปิดงาน") แล้วบันทึกรอบบิลทันที เสี่ยงกดพลาด รอบนี้แยกเป็น 2 ขั้นตอน:
- ปุ่ม **"ดูตัวอย่างก่อนบันทึกรอบบิล"** — เรียกฟังก์ชันใหม่ `previewBillingCandidates` (อ่านข้อมูลอย่างเดียว ไม่มีการเขียนอะไรลงฐานข้อมูล) แสดงตัวอย่างรายการเลขงานที่จะถูกบันทึกในหน้าต่างป๊อปอัป
- ปุ่ม **"ยืนยันบันทึกรอบบิล"** ในหน้าต่างป๊อปอัป — เรียกฟังก์ชันเดิม `generateBillingDocumentsForAllClosedJobs` (ตัวที่บันทึกจริง) ด้วยชุดเงื่อนไขเดียวกับตอนดูตัวอย่างเป๊ะๆ

ฝั่งเซิร์ฟเวอร์เพิ่มฟังก์ชัน `previewBillingCandidates` (เคสใหม่ใน switch) และแยกตรรกะจับคู่เลขงานออกมาเป็นฟังก์ชันกลาง `resolveBillingCandidateJobIds` เพื่อให้ตอนดูตัวอย่างกับตอนบันทึกจริงใช้เงื่อนไขเดียวกันเป๊ะ ไม่มีทางเห็นตัวอย่างอย่างหนึ่งแต่บันทึกได้อีกอย่างหนึ่ง

### 4. บันทึกรายงานสถานะดำเนินการลง Google Sheet ด้วย
เพิ่มแท็บใหม่ชื่อ **"รายงานสถานะดำเนินการ"** ในไฟล์ Google Sheet ปลายทาง จะถูกซิงก์ข้อมูลทุกครั้งที่กด "ซิงก์ข้อมูลไป Google Sheet" เหมือนตารางอื่นๆ

### 5. แก้การซิงก์ Google Sheet ให้เป็น "กระจก" สะท้อนฐานข้อมูลจริงเสมอ
เดิมซิงก์แบบ "เพิ่มต่อท้ายแถวใหม่ + ทำเครื่องหมายว่าซิงก์แล้ว" ซึ่งถ้ามีใครไปลบ/แก้แถวใน Sheet เอง ข้อมูลจะไม่กลับมาซิงก์ใหม่ให้ รอบนี้เปลี่ยนเป็น **ล้างข้อมูลเก่าในแท็บนั้นทั้งหมดแล้วเขียนข้อมูลปัจจุบันจากฐานข้อมูลใหม่ทั้งหมดทุกครั้งที่กดซิงก์** ผลคือ:
- ไม่มีทางเกิดแถวซ้ำ (เพราะเขียนใหม่ทั้งหมดทุกรอบ ไม่ใช่ต่อท้าย)
- ถ้าลบแถวใน Sheet ไปเอง กดซิงก์ครั้งถัดไปจะกลับมาครบเหมือนเดิม (ใช้เป็น backup ต่อเนื่องได้)
- ถ้าข้อมูลในฐานข้อมูลถูกแก้ไข/ลบ กดซิงก์ครั้งถัดไป Sheet จะอัปเดตตามฐานข้อมูลทันที

**หมายเหตุ:** การซิงก์ยังเป็นแบบ "กดเอง" ไม่ใช่อัตโนมัติ — ต้องกดปุ่มซิงก์ในแอปเองทุกครั้งที่ต้องการอัปเดต Sheet ให้ตรงกับฐานข้อมูลล่าสุด

## ถ้ายังไม่ได้ deploy ขั้นตอนนี้

แอปจะยังใช้งานได้ปกติทุกอย่าง เพียงแต่:
- ปุ่ม "ดูตัวอย่างก่อนบันทึกรอบบิล" จะขึ้น error (ยังไม่มีฟังก์ชัน `previewBillingCandidates` ในเซิร์ฟเวอร์)
- สถานะ "พักงาน" ในรายงานจะยังไม่ขึ้น (ค้างเป็น "รอดำเนินการ" เหมือนเดิม)
- การซิงก์ Google Sheet จะยังเป็นพฤติกรรมเดิม (ต่อท้าย ไม่ล้างเขียนใหม่) และยังไม่มีแท็บ "รายงานสถานะดำเนินการ"

deploy เสร็จเมื่อไหร่ ทุกอย่างทำงานทันทีโดยไม่ต้องแตะแอปอีก (แอปเชื่อมกับฟังก์ชันเซิร์ฟเวอร์โดยตรง ไม่ต้อง build ใหม่)

1. เข้า https://supabase.com/dashboard/project/hefnjozijflnhdunmewl/sql/new

3. อ่านผลลัพธ์ตามคำแนะนำในไฟล์ (มีคำสั่งตรวจสอบข้อมูลซ้ำเก่าให้ก่อนแล้ว)
