# อัปเดตรอบนี้ (v1.0.61) — ขั้นตอนติดตั้ง

แก้ **ฝั่งเซิร์ฟเวอร์ + ฝั่งแอป + SQL** · ⚠ **มี SQL ที่รีเซ็ตสถานะอนุมัติทุกงาน ต้องรันทีละบล็อก**

## 1. สลับลำดับการอนุมัติ — TUCK CR ไปอยู่ขั้นสุดท้าย

**ลำดับเดิม:** แอดมินอนุมัติ → ผู้ตรวจสอบ 3 คนกด "สิ้นสุดงาน" (ตัดบิล)

**ลำดับใหม่:**

| ขั้น | ใครกด | กดแล้วเกิดอะไร |
|---|---|---|
| ขั้นที่ 1 | ผู้ตรวจสอบ 3 คน (Superbaipo, Admin, Phutphum) | อนุมัติ / ตีกลับ — **ยังไม่ตัดบิล** · กดคนเดียวใน 3 คนก็ผ่าน |
| ขั้นที่ 2 (สุดท้าย) | **TUCK CR** | อนุมัติขั้นสุดท้าย / ตีกลับ — **ขั้นนี้เท่านั้นที่ตัดบิลจริง** |

**TUCK CR กดขั้นที่ 1 ไม่ได้** ต้องรอให้ผู้ตรวจสอบกดก่อนเสมอ — ถ้าปล่อยให้กดได้ คนเดียวจะกดผ่านครบทั้ง 2 ขั้น การตรวจ 2 ชั้นก็ไม่เหลือความหมาย ระบบจึงบล็อกไว้ทั้งที่ปุ่มและที่เซิร์ฟเวอร์

ชื่อคนกดทั้ง 2 ขั้นยังถูกบันทึกและแสดงเป็นประวัติในตารางเหมือนเดิม (เปลี่ยนแค่คำเรียกเป็น "ขั้นที่ 1 โดย …" และ "ขั้นสุดท้าย อนุมัติโดย …")

> **กันพลาดเพิ่ม** — ผู้ตรวจสอบจะแก้สถานะของงานที่ TUCK CR อนุมัติสุดท้ายไปแล้วไม่ได้ ไม่งั้นจะดึงงานที่ตัดบิล (เก็บเงิน) ไปแล้วกลับมาเป็น "ตีกลับ" ได้

### รีเซ็ตทุกงานให้เริ่มกดใหม่ (ตามที่สั่ง)

บล็อก E ใน SQL จะ:

1. ดึงไฟล์ที่ผู้รับเหมาส่งกลับ **ทุกไฟล์** กลับไปเป็น "รอผู้ตรวจสอบ (ขั้นที่ 1)" ล้างชื่อคนกดและหมายเหตุเดิมทิ้ง
2. **ยกเลิกการตัดบิล** ของงานที่เคยกดสิ้นสุดงานไปแล้ว — งานพวกนั้นจะออกจากเมนู "งานที่เสร็จสิ้น" **กลับเข้าตารางวางบิลของผู้รับเหมาอีกครั้ง** และจะกลับไปเป็น "ตัดบิลแล้ว" ต่อเมื่อมีคนกดครบ 2 ขั้นใหม่
3. **ไฟล์ที่ผู้รับเหมาส่งมาไม่ถูกลบ** ยังอยู่ครบทุกไฟล์

ข้อ 2 แตะข้อมูลเงิน บล็อก D จึงสำรองสถานะเดิมไว้ให้ก่อนเสมอ และมีคำสั่งย้อนกลับเขียนไว้ท้ายไฟล์

## 2. ปิดงานผิดสาขาไม่ได้อีกแล้ว

**เดิม:** ช่องสาขาในฟอร์มปิดงานกรอกอะไรก็ได้ ไม่เคยเทียบกับตอนเปิดงาน กรอกพลาดตัวเดียวงานจะไปโผล่ผิดสาขาทั้งในตารางวางบิล ใบเขียว และรายงาน — ตามแก้ย้อนหลังยากมากเพราะบิลอาจถูกส่งให้ผู้รับเหมาไปแล้ว

**ตอนนี้ อ้างอิงจากเลขงานเป็นหลัก** (1 เลขงาน = 1 สาขาเสมอ) ทำงาน 3 ชั้น:

1. **เติมให้อัตโนมัติ** — พอกรอกเลขงานแล้วคลิกออกจากช่อง ระบบดึงสาขาจากตอนเปิดงานมาเติมให้เลย พร้อมโหลดทะเบียนทรัพย์สินของสาขานั้นใหม่ตาม
2. **เตือนทันที** — ถ้าไปแก้รหัสสาขาทับทีหลังจนไม่ตรง จะขึ้นเตือนสีแดงใต้ช่องทันที และกดบันทึกไม่ผ่าน
3. **เซิร์ฟเวอร์บล็อกอีกชั้น** — เผื่อกรณีใช้แอปรุ่นเก่า จะขึ้นข้อความบอกว่าเลขงานนี้เปิดไว้ที่สาขาไหน

การเทียบไม่สนรูปแบบการเขียน — `0464-บางเสร่` · `0464 บางเสร่` · `0464-0464-บางเสร่` · `464` ถือเป็นสาขาเดียวกันหมด และถ้าข้อมูลตอนเปิดงานไม่มีสาขา (งานเก่าที่กรอกไม่ครบ) จะไม่บล็อก ยังปิดงานได้ตามปกติ

## 🔴 เรื่องสำคัญที่สุด: ปิดรูรั่วราคา CJ หลุดไปหาผู้รับเหมา

ตามที่สั่งให้รีเช็ค — **มีรูรั่วจริง และเจอถึง 4 จุด**

**อาการ:** แถวไหนที่ยังไม่ได้ตั้ง "ราคา/หน่วย (ผู้รับเหมา)" ระบบจะ**เอาราคา CJ มาโชว์แทนให้อัตโนมัติ** ผู้รับเหมาจึงเห็นราคาที่ CR เก็บกับ CJ เต็ม ๆ — ไม่มี error ไม่มีคำเตือน ไม่มีใครรู้จนกว่าผู้รับเหมาจะเอ่ยขึ้นมาเอง

**จุดที่รั่วทั้ง 4:**

| # | จุด | ใครเห็น |
|---|---|---|
| 1 | PDF ใบเขียว / บิลรอบ ฝั่งผู้รับเหมา | ผู้รับเหมาโหลดเอง |
| 2 | ตารางวางบิลบนหน้าจอ | ผู้รับเหมาเปิดแอป |
| 3 | ไฟล์ CSV ฝั่งผู้รับเหมา | ทั้งแอดมินและผู้รับเหมา |
| 4 | CSV ในเมนู "งานที่เสร็จสิ้น" | แอดมินส่งต่อให้ผู้รับเหมา |

**แก้แล้วทั้ง 4 จุด** — ฝั่งผู้รับเหมาอ่านได้เฉพาะคอลัมน์ราคาผู้รับเหมาเท่านั้น แถวที่ยังไม่ได้ตั้งราคาจะขึ้น **ขีดกลาง `-`** และไม่ถูกนับเข้ายอดรวม (นับเป็น 0) ไม่มีทางที่ราคา CJ จะไหลไปฝั่งผู้รับเหมาได้อีก

> ⚠ **ควรตรวจย้อนหลัง** — ใบเขียว/CSV ที่ส่งให้ผู้รับเหมาไปแล้วก่อนอัปเดตนี้ ถ้ามีแถวที่ยังไม่ได้ตั้งราคาผู้รับเหมา ราคา CJ หลุดไปแล้วจริง ๆ · เช็คได้ด้วยการเปิดตารางวางบิลแล้วดูคอลัมน์ "ราคา/หน่วย (ผู้รับเหมา)" ว่ามีแถวไหนว่างอยู่บ้าง

## 2 เรื่องที่แก้เพิ่มล่าสุดที่สุด

### ราคารวมคำนวณสดทันทีที่พิมพ์ — ทั้ง CJ และผู้รับเหมา

เดิมต้องกดบันทึกก่อนถึงจะเห็นว่าราคารวมได้เท่าไหร่ ตอนนี้**พิมพ์ปุ๊บเห็นปั๊บ**

```
ราคารวม = จำนวน × ราคาต่อหน่วย
```

**ใช้สูตรเดียวกันเป๊ะทั้ง 2 ฝั่ง** — แก้ `จำนวน` หรือ `ราคา/หน่วย` → `ราคา/รวม` เปลี่ยนทันที · แก้ `ราคา/หน่วย (ผู้รับเหมา)` → `ราคา/รวม (ผู้รับเหมา)` เปลี่ยนทันที · และเป็นสูตรเดียวกับที่เซิร์ฟเวอร์ใช้ตอนบันทึก ตัวเลขบนจอกับในฐานข้อมูลจึงไม่มีทางเพี้ยนกัน

ช่องราคาที่เว้นว่างไว้ ราคารวมจะว่างตาม ไม่ใส่ 0 ให้ เพราะ 0 แปลว่า "ตั้งราคาไว้ 0 บาทจริง ๆ" ซึ่งคนละความหมายกับ "ยังไม่ได้ตั้งราคา"

> **เจอบั๊กเพิ่มระหว่างทำ** — สูตรฝั่งเซิร์ฟเวอร์ใช้ `?? 0` ซึ่งกันได้แค่ `null`/`undefined` แต่ `parseFloat('')` คืน `NaN` ที่รอดผ่านไปได้ สุดท้ายเอา `NaN` ไปคูณแล้วเขียนลงคอลัมน์ตัวเลข = **อัปเดตพังทั้งแถว** ถ้าเผลอลบราคาจนว่างแล้วกดบันทึก · แก้ให้บังคับเป็นตัวเลขจริงเสมอแล้ว

### หน้าต่างเพิ่มอะไหล่ — แก้จำนวนของอะไหล่เดิมได้เลย

เปลี่ยนรายการอะไหล่ที่มีอยู่แล้วจากตารางดูอย่างเดียว เป็น**การ์ดหน้าตาเดียวกับกล่องเพิ่มอะไหล่** และ**แก้ "จำนวน" ได้ตรงนั้นเลย** มีปุ่มบันทึกของตัวเองแต่ละชิ้น

กดบันทึกแล้วเซิร์ฟเวอร์คำนวณราคารวมทั้ง 2 ฝั่งให้ใหม่ และแสดงผลกลับมาให้เห็นทันที พร้อมวาดตารางวางบิลข้างหลังใหม่ให้ตรงกัน

การ์ดยังโชว์ ราคา/หน่วย ทั้ง CJ และ ผรม. · ชิ้นที่ยังไม่ได้ตั้งราคาผู้รับเหมาขึ้น **"ยังไม่ตั้งราคา"** สีส้ม · ช่องอื่นนอกจากจำนวนยังแก้ที่ตารางวางบิลเหมือนเดิม

## 3 เรื่องที่แก้รอบก่อนหน้า

### ปฏิทินกดแล้วไม่ขึ้น — เจอสาเหตุแล้ว

โค้ดเดิมคำนวณตำแหน่งพาเนลปฏิทินโดย**บวกระยะที่เลื่อนหน้าจอ (`window.scrollY`) เข้าไปด้วย**

แต่พาเนลนี้เป็น `position:fixed` ซึ่งใช้พิกัดเทียบ **กรอบหน้าจอ** ไม่ใช่เทียบทั้งหน้าเอกสาร และค่าที่วัดมาก็เป็นพิกัดเทียบกรอบหน้าจออยู่แล้ว พอบวก scroll เข้าไปอีก พาเนลจึงถูกดันลงไปไกลเท่ากับระยะที่เลื่อนมา

นี่คือเหตุผลที่**อยู่บนสุดของหน้ากดได้ แต่พอเลื่อนลงมาที่ตารางวางบิลแล้วกดไม่ขึ้น** — พาเนลไปโผล่นอกจอ

แก้แล้ว: ตัด scroll ออก และเพิ่มการกันล้นขอบจอ ถ้าข้างล่างไม่พอจะกางขึ้นข้างบนช่องแทน · มีผลกับปฏิทินทุกช่องในแอป

### ช่องในตารางแคบจนเลขโดนตัด

ช่องกรอกเป็น `w-full` แล้วปล่อยให้ตารางบีบเอง พอคอลัมน์เยอะ ช่องราคาจะแคบจนเห็นเป็น `175(` แทน `1750` — อ่านไม่ออกและแก้ไม่ถูกเพราะมองไม่เห็นว่าพิมพ์อะไรอยู่

แก้แล้ว: กำหนดความกว้างขั้นต่ำรายคอลัมน์ ตั้งจากค่าที่ยาวที่สุดเท่าที่เป็นไปได้จริง (ราคาหลักล้านมีทศนิยม · เลขทรัพย์สิน 12 หลัก · วันที่ dd/mm/yyyy) · ถ้ารวมแล้วกว้างเกินจอ ตารางจะเลื่อนแนวนอนได้ตามปกติ

**ขยายเพิ่มอีกรอบ** สำหรับ 3 ช่องที่ต้องอ่านและแก้บ่อยที่สุดตอนตรวจอะไหล่:

| ช่อง | เดิม | ใหม่ | เหตุผล |
|---|---|---|---|
| จำนวน | 64px | **105px** | รองรับทศนิยม เช่น 1.6 กก. / 0.75 เมตร |
| หน่วย | 70px | **110px** | คำไทยยาวสุดคือ "กิโลกรัม" |
| ราคา/หน่วย (CJ) | 100px | **140px** | หลักล้านมีทศนิยม 1,234,567.89 |

ราคา/รวม และช่องฝั่งผู้รับเหมาขยายตามให้สมดุลกันด้วย

**ซ่อนลูกศรขึ้น-ลงของช่องตัวเลข** — ลูกศรคู่นี้กินความกว้างในช่องไปราว 16-18px ทำให้ตัวเลขยาว ๆ ถูกเบียดจนโดนตัด และแทบไม่มีใครใช้กดทีละหน่วยอยู่แล้ว · ยังพิมพ์ตัวเลข ทศนิยม และกดลูกศรบนคีย์บอร์ดได้เหมือนเดิมทุกอย่าง

**เจอจุดที่ขัดกันเอง** — หัวตารางช่อง "จำนวน" ถูกใส่ `w-16` (64px) ไว้ตายตัว ซึ่งสู้กับความกว้างขั้นต่ำที่ตั้งให้ช่องข้อมูล ทำให้ช่องถูกบีบกลับ · เอาออกแล้ว

ตาราง **"งานที่เสร็จสิ้น"** มีปัญหาเดียวกัน (ใช้ `w-16`/`w-20` ตายตัว) ขยายให้เท่ากันแล้ว

### ค้นหาแล้วเด้งข้อมูลมาเลย ไม่ต้องเลือกรอบบิล

เดิมช่องค้นหากรองเฉพาะแถวที่โหลดมาแล้ว ซึ่งมีแค่ "งานที่ยังไม่ตัดบิล" หรือรอบที่เลือกไว้ — งานที่ตัดบิลไปแล้วหาไม่เจอเลยถ้าไม่รู้ว่าอยู่รอบไหน

ตอนนี้**ยิงไปค้นที่เซิร์ฟเวอร์ ค้นข้ามทุกรอบบิลและทุกสถานะ** พิมพ์เลขงานแล้วเจอทันที เข้าไปแก้อะไหล่ย้อนหลังได้เลย · ค้นได้ทั้ง เลขงาน / เลขทรัพย์สิน / รหัสอะไหล่ / ชื่อสาขา · หน่วง 400ms ก่อนยิง ไม่ยิงทุกตัวอักษร

> ⚠ **ข้อแลกเปลี่ยนที่ต้องรู้:** ผลการค้นกลายเป็น "ข้อมูลที่โหลดอยู่" จึง**มีผลกับปุ่มดาวน์โหลดด้วย** ต่างจากเดิมที่ค้นแล้วไม่กระทบการออกบิล
> ถ้าลืมล้างคำค้นแล้วกด CSV จะได้บิลเฉพาะแถวที่ค้นเจอ = **เก็บเงินขาด**
> จึงใส่ป้ายเตือนสีเหลืองขึ้นตลอดเวลาที่ยังค้นอยู่ พร้อมข้อความว่า *"ปุ่มดาวน์โหลดจะออกเฉพาะแถวที่ค้นเจอนี้เท่านั้น ล้างคำค้นก่อนออกบิลจริง"*
> ผู้รับเหมาค้นได้เฉพาะงานของตัวเองที่ถูกส่งบิลแล้วเหมือนเดิมทุกประการ

## 4 เรื่องที่สั่งมา

### 1. ช่องรายละเอียดอะไหล่ตัดเป็น 2 บรรทัด

คอลัมน์ "รายละเอียดอะไหล่" เปลี่ยนจากช่องบรรทัดเดียวเป็น **ช่องกรอกสูง 2 บรรทัด** ชื่ออะไหล่ยาว ๆ อย่าง `คอมเพรสเซอร์ EMBRACO NEK6210Z R134a 1/2HP 220V` อ่านครบโดยไม่ต้องเลื่อนในช่อง · ลากขยายเองได้ถ้ายังไม่พอ · ฝั่งผู้รับเหมาที่เป็นแบบดูอย่างเดียวก็ตัดบรรทัดให้เหมือนกัน

### 2. แก้ราคา/หน่วย ได้ทีหลัง — ทั้งฝั่ง CJ และฝั่งผู้รับเหมา

ช่องราคาทั้ง 2 ฝั่ง**แก้ได้อยู่แล้วตั้งแต่เดิม** แต่แก้แล้วไม่ติด เพราะมี 2 สาเหตุซ้อนกัน

**สาเหตุที่ 1 — ราคาถูกดึงจากคลังมาทับ (ตัวหลัก)**

ระบบผูกการดึงราคาไว้กับการ "คลิกออกจากช่อง Part Code" แล้ว**ดึงทุกครั้งที่คลิกออก ถึงจะไม่ได้แก้รหัสเลยก็ตาม** จากนั้นเขียนทับ ราคา CJ · ราคาผู้รับเหมา · รายละเอียด · หน่วย ด้วยค่าจากคลังทันที

ผลคือ แอดมินแก้ราคาเองไว้ พอเผลอคลิกผ่านช่อง Part Code ทีเดียว ราคาที่แก้ก็กลับเป็นราคาคลังทันที **เงียบสนิท ไม่มีข้อความเตือน** เลยรู้สึกว่า "แก้ราคาแล้วไม่ติด"

แก้แล้ว: ดึงราคาจากคลัง**เฉพาะตอนที่รหัสอะไหล่เปลี่ยนจริง ๆ** เท่านั้น · รหัสเดิม = ไม่แตะอะไรเลย ราคาที่แก้เองอยู่ครบ · เปลี่ยนรหัสจริงถึงดึงใหม่ (คนละอะไหล่ = ราคาใหม่ ถูกต้องแล้ว) · แก้ทั้ง 2 ตาราง คือตารางวางบิลหลัก และตารางในเมนู "งานที่เสร็จสิ้น"

**สาเหตุที่ 2 — ช่องราคารวมไม่อัปเดต**

พอกดบันทึก ช่อง "ราคา/รวม" ยังโชว์เลขเก่าค้างอยู่ ต้องโหลดตารางใหม่ถึงจะเห็นเลขที่ถูก

แก้แล้ว: เซิร์ฟเวอร์ส่งแถวที่คำนวณเสร็จกลับมาด้วย ช่องราคารวมทั้ง 2 ฝั่งอัปเดตทันทีที่กดบันทึก ทั้ง 2 ตาราง

### 3. กด + แล้วเห็นอะไหล่ที่มีอยู่แล้ว

กดปุ่ม **+** ที่แถวไหน หน้าต่างเพิ่มอะไหล่จะแสดง**ตารางอะไหล่ที่ผูกกับเลขทรัพย์สินนั้นอยู่แล้ว**ไว้ด้านบนก่อน — Part Code · รายละเอียด · จำนวน · ราคา CJ · ราคาผู้รับเหมา · ประเภทเก็บเงิน

ช่องราคาผู้รับเหมาที่ยังว่างจะขึ้น **"ยังไม่ตั้ง"** สีส้ม เห็นได้ทันทีว่าชิ้นไหนต้องกลับไปแก้ · เป็นตารางดูอย่างเดียว แก้จริงที่ตารางวางบิลเหมือนเดิม · อ่านจากข้อมูลที่โหลดไว้แล้ว ขึ้นทันทีไม่ต้องรอ

### 4. เมนูใหม่: ใบเขียวผู้รับเหมา ตามช่วงวันที่

กล่องสีเขียวน้ำทะเลในหน้าตารางวางบิล — เลือกช่วงวันแล้วโหลดใบเขียวได้เลย **ข้ามรอบบิลได้** ไม่ต้องไล่โหลดทีละรอบ

- **เลือกได้ว่าจะกรองด้วยวันไหน** — วันที่เข้างาน หรือ วันที่รับแจ้ง
- เลือกผู้รับเหมาเจาะจง หรือเอาทุกคนรวมในใบเดียว
- **ไม่ใช้ข้อมูลบนหน้าจอเลย** ให้เซิร์ฟเวอร์ไปดึงใหม่ตามช่วงวัน จึงได้ครบทั้งระบบ ไม่ถูกจำกัดด้วยตัวกรองที่เลือกค้างไว้
- ดึงทีละ 1,000 แถวจนหมด กันข้อมูลได้ไม่ครบแบบเงียบ ๆ เมื่อข้อมูลสะสมหลายปี
- **ใช้ราคาผู้รับเหมาล้วนเสมอ** ต่อให้คนกดเป็นแอดมิน ราคา CJ ไม่ปนออกไปเด็ดขาด

> วันที่ในระบบเก็บเป็นข้อความ `DD/MM/YYYY` กรองใน SQL ตรง ๆ ไม่ได้ จึงดึงมาแปลงแล้วกรองฝั่งเซิร์ฟเวอร์ · แถวที่อ่านวันที่ไม่ออก (ข้อมูลเก่ารูปแบบเพี้ยน) จะไม่ถูกนับเข้าช่วง ระบบไม่เดาให้


**วิธีเช็คว่าได้ผลจริง — ข้อ 1 สำคัญที่สุด:**

1. **เช็ครูรั่ว** — หาแถวที่ช่อง "ราคา/หน่วย (ผู้รับเหมา)" ว่างอยู่ → ล็อกอินเป็นผู้รับเหมาคนนั้น → ตารางต้องขึ้น **`-`** ที่ช่องราคา **ห้ามขึ้นตัวเลขราคา CJ เด็ดขาด** → โหลด PDF ใบเขียวก็ต้องขึ้น `-` เหมือนกัน
2. คอลัมน์รายละเอียดอะไหล่ต้องเป็นช่อง 2 บรรทัด
3. **ทดสอบราคาแก้แล้วไม่โดนทับ** — แก้ "ราคา/หน่วย" (CJ) และ "ราคา/หน่วย (ผู้รับเหมา)" เป็นเลขที่ตั้งเอง → **คลิกเข้าช่อง Part Code แล้วคลิกออกโดยไม่แก้รหัส** → ราคาที่ตั้งไว้ต้องยังอยู่ครบ ห้ามเด้งกลับเป็นราคาคลัง → กดบันทึก ช่อง "ราคา/รวม" ทั้ง 2 ฝั่งต้องเปลี่ยนทันทีโดยไม่ต้องโหลดใหม่
   - ลองเปลี่ยนรหัสอะไหล่เป็นรหัสอื่นด้วย → คราวนี้ราคา**ต้อง**ถูกดึงมาใหม่ตามรหัสใหม่
4. กด **+** ที่แถวที่มีอะไหล่อยู่แล้ว → ต้องเห็นตารางอะไหล่เดิมด้านบน
5. กล่องสีเขียวน้ำทะเล → เลือกช่วงวัน กดดาวน์โหลด → ได้ PDF และราคาต้องเป็นราคาผู้รับเหมา
6. **ปฏิทิน** — เลื่อนหน้าจอลงมาที่ตารางวางบิลก่อน แล้วค่อยกดช่องวันที่ → ปฏิทินต้องเด้งขึ้นตรงใต้ช่อง (เดิมกดแล้วไม่ขึ้นเพราะไปโผล่นอกจอ) · ลองทั้งช่องบนสุดและช่องล่างสุดของหน้า
7. **ความกว้างช่อง** — ช่อง **จำนวน / หน่วย / ราคา-หน่วย (CJ)** ต้องกว้างพอเห็นค่าเต็ม ไม่โดนตัดเป็น `175(` · ลองใส่ราคาหลักล้าน `1234567.89` และหน่วย `กิโลกรัม` ดูว่าเห็นครบไหม · เช็คทั้งตารางวางบิลและตาราง "งานที่เสร็จสิ้น"
8. **ค้นหา** — ตั้งตัวกรองรอบบิลเป็น "ทุกรอบ" แล้วพิมพ์เลขงานที่**ตัดบิลไปแล้ว** → ต้องเจอทันทีโดยไม่ต้องเลือกรอบ และต้องมีป้ายเหลืองเตือนเรื่องปุ่มดาวน์โหลดขึ้นมาด้วย
9. **ราคารวมสด** — แก้ `จำนวน` → `ราคา/รวม` ทั้ง 2 ฝั่งต้องเปลี่ยนทันทีโดยยังไม่กดบันทึก · แก้ `ราคา/หน่วย` → เฉพาะ `ราคา/รวม` ฝั่ง CJ เปลี่ยน · แก้ `ราคา/หน่วย (ผรม.)` → เฉพาะฝั่ง ผรม. เปลี่ยน · กดบันทึกแล้วเลขต้องเท่าเดิมไม่กระโดด
   - **ลบราคาจนว่างแล้วกดบันทึก** → ต้องบันทึกผ่าน ไม่ error (บั๊ก NaN ที่แก้ไป)
10. **แก้จำนวนในหน้าต่างเพิ่มอะไหล่** — กด **+** ที่แถวที่มีอะไหล่อยู่แล้ว → แก้จำนวนในการ์ด กดบันทึกจำนวน → ต้องขึ้นราคารวมใหม่ทั้ง 2 ฝั่ง และตารางข้างหลังต้องเปลี่ยนตาม
