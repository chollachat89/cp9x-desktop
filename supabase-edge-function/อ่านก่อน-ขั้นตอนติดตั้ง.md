# กันเลขงานซ้ำ + แสดงช่วงเวลาพักงาน — ขั้นตอนติดตั้งฝั่งเซิร์ฟเวอร์

โปรเจกต์นี้ใช้ Electron (แอปหน้าเว็บ) คู่กับ Supabase Edge Function เป็นเซิร์ฟเวอร์หลังบ้าน
โฟลเดอร์นี้คือไฟล์ที่ต้องเอาไป **วางบน Supabase Dashboard เอง** — เครื่องมือ Cowork ที่ผมใช้อยู่เชื่อมกับบัญชี Supabase คนละบัญชีกับที่ดูแลฐานข้อมูลจริงของ CP9X จึงแก้ให้จากตรงนี้อัตโนมัติไม่ได้ ต้องมีคนที่มีสิทธิ์เข้า Dashboard ของโปรเจกต์ `hefnjozijflnhdunmewl` ทำ 2 ขั้นตอนด้านล่างนี้

ถ้าคุณไม่ใช่คนดูแล Supabase ให้ส่งไฟล์ในโฟลเดอร์นี้ (`index.ts` และ `add-unique-constraints.sql`) พร้อมเอกสารนี้ให้คนที่ดูแลอยู่แทน

---

## ขั้นที่ 1 — รัน SQL กันซ้ำที่ฐานข้อมูล (ทำก่อนเสมอ)

1. เข้า https://supabase.com/dashboard/project/hefnjozijflnhdunmewl/sql/new
2. เปิดไฟล์ `add-unique-constraints.sql` ในโฟลเดอร์นี้ คัดลอกเนื้อหาทั้งหมด
3. วางใน SQL Editor แล้วกด **Run**
4. ไฟล์นี้มีคำสั่งตรวจสอบข้อมูลซ้ำเก่าไว้ให้ก่อนแล้ว — **อ่านผลลัพธ์ตามคำแนะนำในไฟล์**
   - ถ้าคำสั่งตรวจสอบ 2 อันแรกไม่คืนแถวใดเลย = ปลอดภัย ไปต่อได้
   - ถ้าคืนแถวมา = มีเลขงานซ้ำในข้อมูลเก่าอยู่แล้ว ต้องแก้ไขให้เรียบร้อยก่อน ไม่งั้นคำสั่งสร้าง index ท้ายไฟล์จะรันไม่ผ่าน

## ขั้นที่ 2 — อัปเดตโค้ด Edge Function

1. เข้า https://supabase.com/dashboard/project/hefnjozijflnhdunmewl/functions/app-api
2. กด **Edit function** (หรือปุ่มแก้ไขโค้ด)
3. เปิดไฟล์ `index.ts` ในโฟลเดอร์นี้ คัดลอกเนื้อหาทั้งหมด
4. **ลบโค้ดเดิมทั้งหมดในหน้าแก้ไขของ Supabase แล้ววางโค้ดใหม่แทนทั้งไฟล์**
5. กด **Deploy** / **Save and Deploy**
6. รอสัก 10–20 วินาทีให้ deploy เสร็จ

---

## นี่คือการเปลี่ยนแปลงอะไรบ้าง

ไฟล์ `index.ts` เป็น**โค้ดเดิมทั้งหมด 100%** บวกเพิ่ม 5 จุดนี้เท่านั้น (ไม่มีอะไรถูกลบหรือแก้พฤติกรรมเดิม):

1. **`saveOpenIssue`** — เพิ่มการเช็คก่อนบันทึกว่าเลขที่ใบแจ้งซ่อมบำรุงนี้เปิดงานไปแล้วหรือยัง ถ้าซ้ำจะไม่บันทึกและแจ้งข้อความชัดเจน
2. **`saveCloseIssue`** — เพิ่มการเช็คก่อนบันทึกว่าเลขนี้ปิดงานไปแล้วหรือยัง ถ้าซ้ำจะไม่บันทึก
3. **`checkCloseIssueExists`** (ฟังก์ชันใหม่) — ให้หน้าเว็บเรียกเช็คสถานะปิดงานได้แบบเดียวกับที่มี `checkOpenIssueExists` อยู่แล้ว
4. **ดักจับการชนกันแบบพร้อมกันเป๊ะ ๆ** (error code `23505` จาก Postgres) — เป็นด่านสุดท้ายกรณีสองคนกดบันทึกในเสี้ยววินาทีเดียวกันจนเช็คก่อนหน้าไม่ทัน จะยังคงกันซ้ำได้อยู่ (ด่านนี้ทำงานได้จริงก็ต่อเมื่อรัน SQL ในขั้นที่ 1 แล้วเท่านั้น)
5. **`getJobStatusReport`** — เพิ่มข้อมูลช่วงเวลาพักงาน (`pause_periods`, `pause_count`, `pause_hours_total`) แนบไปกับแต่ละแถวงาน เพื่อให้หน้า "ดูรายละเอียด" ในแอปแสดงช่วงเวลาที่งานถูกพักได้

ฝั่งแอป (Electron) แก้ไขและปล่อยเวอร์ชันใหม่ให้เรียบร้อยแล้วในตัว — เชื่อมกับฟังก์ชันใหม่พวกนี้อัตโนมัติทันทีที่ deploy เสร็จ **ไม่ต้องรอ build แอปใหม่**

## ถ้ายังไม่ได้ deploy ขั้นที่ 2

แอปจะยังใช้งานได้ปกติทุกอย่าง เพียงแต่:
- การเช็คกันซ้ำตอนกรอกเลขงาน (ทั้งตอนพิมพ์และตอนกดบันทึก) จะยังไม่ทำงาน — ระบบจะปล่อยให้บันทึกผ่านเหมือนเดิม (ไม่ error ไม่ค้าง)
- ช่องแสดง "ช่วงเวลาพักงาน" ในหน้าดูรายละเอียดจะโชว์ "-" ไปก่อน

deploy เสร็จเมื่อไหร่ ทุกอย่างทำงานทันทีโดยไม่ต้องแตะแอปอีก
