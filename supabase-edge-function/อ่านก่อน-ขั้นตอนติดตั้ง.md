# อัปเดตรอบนี้ (v1.0.17) — ขั้นตอนติดตั้ง

รอบนี้แก้ **เฉพาะฝั่งเซิร์ฟเวอร์ (Supabase Edge Function)** อย่างเดียว — ไม่มี SQL ใหม่ ไม่ต้อง build ฝั่งหน้าแอปก็ได้ (ฟีเจอร์นี้อยู่ในเซิร์ฟเวอร์ล้วนๆ ทั้ง PDF และ Excel)

**เปลี่ยนโทนสีใบเสนอราคา PM ทั้งใบเป็นโทนเขียวมิ้นท์ ตามแบบฟอร์ม "Tax Invoice/Invoice" ของ SME MOVE ที่ส่งมาเป็นตัวอย่าง** — ปรับให้เข้ากับงานของเรา (คงชื่อเอกสาร "ใบเสนอราคา / QUOTATION" และเลขที่เอกสารรูปแบบเดิม `CRE-CJ-PM-6908-0001` ไว้ตามเดิม ไม่เปลี่ยนเป็นแบบ Invoice ของแบบฟอร์มตัวอย่าง) มีการเปลี่ยนแปลงดังนี้:

1. หัวเอกสารเพิ่มกล่องสีเขียวคำว่า "ใบเสนอราคา / QUOTATION" พร้อมกล่องเลขที่เอกสาร (พร้อมคำว่า "ต้นฉบับ / Original") อยู่ข้างๆ กัน
2. หัวตารางรายการ (Item/Description/Qty/Unit/Unit Price/Amount) เปลี่ยนจากพื้นดำเป็นพื้นเขียว ตัวหนังสือสีขาวเหมือนเดิม
3. แถว Grand Total เปลี่ยนจากไฮไลท์สีส้มเป็นสีเขียว ตัวหนังสือสีขาว
4. เปลี่ยนส่วนลายเซ็นท้ายเอกสารเป็นกล่อง 3 ช่อง (ผู้รับวางบิล / เว้นว่างสำหรับประทับตรา / ผู้มีอำนาจลงนามพร้อมลายเซ็นจริง) มีเส้นขอบล้อมรอบชัดเจน
5. เพิ่มแถบสีเขียวท้ายกระดาษทุกหน้า แสดงชื่อบริษัทและที่อยู่ ตัวหนังสือสีขาว (ฝั่ง PDF มีการคำนวณพื้นที่เว้นว่างเพิ่มพิเศษเพื่อไม่ให้แถบนี้ทับกับรายการสุดท้ายบนหน้าที่มีรายการเยอะ ทดสอบแล้วกับ 120 รายการ 4 หน้า ไม่มีปัญหาซ้อนทับ)

ทำทั้งฝั่ง PDF และฝั่ง Excel ให้ตรงกันแบบเดียวกันทั้งคู่ ทดสอบซ้ำแล้วทั้งกรณีรายการน้อย/รายการเยอะ (120 รายการ) ไม่มีปัญหาซ้อนทับหรือข้อความล้นกล่อง

## ขั้นตอนติดตั้ง v1.0.17 (ขั้นเดียว)

1. เข้า https://supabase.com/dashboard/project/hefnjozijflnhdunmewl/functions/app-api → **Edit function**
2. คัดลอก `index.ts` ในโฟลเดอร์นี้วางแทนทั้งไฟล์ → **Deploy** รอสัก 10–20 วินาที
3. ลองดาวน์โหลดทั้ง PDF และ Excel ของรอบบิลดูอีกครั้ง

# อัปเดตรอบก่อนหน้า (v1.0.14) — ขั้นตอนติดตั้ง

## นี่คือการเปลี่ยนแปลงอะไรบ้าง (v1.0.14)

1. **แก้บั๊ก Description ซ้ำรหัสสาขา** — พบว่า `branch_name` ในฐานข้อมูลระบบ PM จริงมีรหัสสาขาติดมาให้อยู่แล้ว (เช่น `"1349-ตลาดเมืองใหม่มาร์เก็ต เคหะบางพลี"`) ตอนเอา `branch_code` มาต่อหน้าอีกทีเลยกลายเป็น `"1349-1349-..."` ซ้ำกัน — แก้ทั้งฝั่งสร้าง PDF และฝั่งตารางแก้ไขในหน้าแอปให้เช็คก่อนว่า branch_name ขึ้นต้นด้วยรหัสสาขาอยู่แล้วหรือยัง ถ้าใช่ก็ใช้ตรงๆ ไม่ต่อซ้ำ

3. **เพิ่มเมนู "ประวัติบิล PM"** — ปุ่มใหม่ในหน้า PM (ถัดจากปุ่มดูตัวอย่าง) เปิด popup แสดงรอบบิล PM ที่เคยบันทึกไว้ทั้งหมด พร้อมเลขที่เอกสาร/รอบ PM/จำนวนรายการ/ยอดรวม/วันที่บันทึก และปุ่มดาวน์โหลด PDF ย้อนหลังต่อรอบ โดยไม่ต้องไล่เลือกทีละรอบจากตัวกรองหลักเหมือนเดิม

# อัปเดตรอบก่อนหน้า (v1.0.11) — ขั้นตอนติดตั้ง

รอบนี้แก้ **เฉพาะฝั่งเซิร์ฟเวอร์ (Supabase Edge Function)** อย่างเดียว — ไม่มี SQL ใหม่ ไม่ต้องแก้/build ฝั่งหน้าแอปก็ได้ (แต่แนะนำให้เพิ่มเวอร์ชันตามไปด้วยเพื่อให้เลขเวอร์ชันตรงกัน)

**แก้บั๊ก:** PDF ใบเสนอราคา PM ตัวอักษรซ้อนทับกัน (ข้อความ " - รายการอื่น ๆ ที่มิได้ระบุไว้ข้างต้น" ไปทับกับแถวรายการสุดท้าย) เมื่อรอบบิลมีรายการจำนวนมาก (เช่น 120 รายการ) — ทดสอบซ้ำบั๊กนี้ในเครื่องด้วยข้อมูลจำลอง 120 แถวแล้ว ต้นเหตุคือช่องว่างระหว่างเส้นขอบล่างของแถวสุดท้ายกับข้อความ "รายการอื่นๆ" เดิมเว้นไว้แค่ 4pt ซึ่งแคบเกินไปสำหรับตัวอักษรไทย (สระ/วรรณยุกต์ที่ลอยเหนือ-ใต้ตัวพยัญชนะกินพื้นที่แนวตั้งมากกว่าอังกฤษ) รอบนี้ขยายช่องว่างเป็น 14pt และปรับเผื่อพื้นที่ท้ายเอกสารเพิ่มตาม พร้อมทั้งขยายคอลัมน์ "Amount" เล็กน้อย (หด Item/Qty ที่เหลือพื้นที่อยู่แล้วลง) กันยอดรวมหลักล้านถูกตัดข้อความ ตรวจสอบซ้ำด้วยการ render PDF จริงทั้งกรณี 7 รายการและ 120 รายการ (4 หน้า) ไม่พบซ้อนทับอีกแล้ว ขนาดหน้ายังเป็น A4 แนวตั้งเหมือนเดิม (ไม่ได้เปลี่ยนเป็น Letter)

# อัปเดตรอบก่อนหน้า (v1.0.10) — ขั้นตอนติดตั้ง

รอบนี้แก้ 3 อย่าง: **SQL ใหม่ 1 ไฟล์** + **ฝั่งเซิร์ฟเวอร์ (Supabase Edge Function)** + **ฝั่งหน้าแอป (Electron)** — ต้องทำครบทั้ง 3 ไม่งั้นฟีเจอร์ใหม่จะไม่ครบ/พัง

โปรเจกต์นี้ใช้ Electron (แอปหน้าเว็บ) คู่กับ Supabase Edge Function เป็นเซิร์ฟเวอร์หลังบ้าน
โฟลเดอร์นี้คือไฟล์ที่ต้องเอาไป **วางบน Supabase Dashboard เอง** — เครื่องมือ Cowork ที่ผมใช้อยู่เชื่อมกับบัญชี Supabase คนละบัญชีกับที่ดูแลฐานข้อมูลจริงของ CP9X (โปรเจกต์ `hefnjozijflnhdunmewl`) จึงแก้ให้จากตรงนี้อัตโนมัติไม่ได้ ต้องมีคนที่มีสิทธิ์เข้า Dashboard ทำขั้นตอนด้านล่างนี้ (ฝั่งระบบ PM เอง — โปรเจกต์ `ucxzsfiktqswabxfnojr` "SuperDatabase" — ไม่ต้องแตะอะไรเพิ่มรอบนี้)

ถ้าคุณไม่ใช่คนดูแล Supabase/ไม่ใช่คนที่ build แอป ให้ส่งไฟล์ `index.ts`, `add-pm-manual-line-item.sql` ในโฟลเดอร์นี้ พร้อมเอกสารนี้ให้คนที่ดูแลอยู่แทน

## ขั้นที่ 3 — build แอปเวอร์ชันใหม่แล้วปล่อยอัปเดต (บังคับ ต้องทำ)

รอบนี้แก้ไฟล์หน้าแอป `src/renderer/index.html` ด้วย (บังคับเลือกช่วงวันที่ก่อนดูตัวอย่าง PM, ปุ่ม "เพิ่มรายการเอง", ซ่อนเมนู PM จากผู้รับเหมา) ไฟล์นี้ถูกฝังไปกับตัวติดตั้งของแอป (`.exe`) ตอน build **ไม่ใช่ดึงจากเซิร์ฟเวอร์แบบ Edge Function** ดังนั้นแก้ไฟล์นี้แล้ว "ไม่มีผลอะไรกับเครื่องผู้ใช้จนกว่าจะ build เวอร์ชันใหม่แล้วปล่อยอัปเดต":

1. เปิด terminal ที่โฟลเดอร์ `cp9x-desktop` (โฟลเดอร์แม่ของโฟลเดอร์นี้)
2. รัน `npm install` ถ้ายังไม่เคยรัน
3. รัน `npm run release` (ตั้งไว้ให้ publish อัตโนมัติผ่าน electron-builder — ถ้ายังไม่เคยตั้งค่าที่ publish ปลายทางไว้ ให้รัน `npm run build` แทนเพื่อได้ไฟล์ติดตั้งในโฟลเดอร์ `dist/` มาแจกเองก่อน)
4. เวอร์ชันในแอปตอนนี้คือ `1.0.10` (แก้ไว้ใน `package.json` แล้ว) — ผู้ใช้ที่เปิดแอปเวอร์ชันเก่าอยู่จะได้รับอัปเดตอัตโนมัติผ่าน electron-updater (ถ้าตั้งค่า publish/update server ไว้แล้ว) หรือให้โหลดตัวติดตั้งใหม่ไปลงเอง

**สำคัญ — ขั้นที่ 2 (Edge Function) เปลี่ยนพฤติกรรมเดิม:** หลัง deploy ขั้นที่ 2 เสร็จ ปุ่ม "ดูตัวอย่างก่อนบันทึกรอบบิล PM" จะ**บังคับให้เลือกช่วงวันที่ก่อนเสมอ** (เมื่อก่อนเว้นว่างได้ = ดึงมาทั้งหมด) — ถ้าตอนนั้นแอปเวอร์ชันเก่ายังไม่ได้ build ใหม่ (ยังไม่ทำขั้นที่ 3) ผู้ใช้ที่กดดูตัวอย่างโดยไม่ได้เลือกวันที่จะเจอ error แจ้งให้เลือกวันที่ก่อน (ไม่พัง แค่ต้องเลือกวันที่) — แนะนำให้ทำขั้นที่ 3 ต่อให้เสร็จในรอบเดียวกันเพื่อให้หน้าตาช่องกรอกวันที่ชัดเจนขึ้นด้วย

## นี่คือการเปลี่ยนแปลงอะไรบ้าง (รอบนี้ v1.0.10)

1. **ใบเสนอราคา PM ตรงกับไฟล์ตัวอย่างฉบับสมบูรณ์ที่ส่งมา (`CRE-CJ-PM-6908-0001.xlsx`) เป๊ะขึ้น:**
   - Description แต่ละแถวเปลี่ยนจาก "รหัสสาขา ชื่อสาขา" (เว้นวรรค) เป็น "รหัสสาขา-ชื่อสาขา" (ขีดกลาง) ตามต้นฉบับ เช่น `0040-เมืองทอง`
   - เอาบรรทัด " - ค่าน้ำ, ค่าไฟฟ้าที่ใช้ในหน่วยงาน" ออก เหลือบรรทัดเดียวคือ " - รายการอื่น ๆ ที่มิได้ระบุไว้ข้างต้น" ตามไฟล์ฉบับสมบูรณ์
   - เลขที่เอกสาร ("เลขที่/No.") เปลี่ยนจาก `PM-{เลขรอบบิล}` เป็นรูปแบบ `CRE-CJ-PM-{ปี พ.ศ. 2 หลัก}{เดือน 2 หลัก}-{ลำดับ 4 หลัก}` ตรงกับไฟล์ตัวอย่าง (เช่น `CRE-CJ-PM-6908-0001`) — ปี/เดือนอิงจากวันที่สร้างรอบบิลนั้น (ไม่ใช่วันที่กดดาวน์โหลด กันเลขเปลี่ยนไปมา) ลำดับ 4 หลักนับจากรอบบิล PM ที่เคยสร้างในเดือน/ปีเดียวกัน
2. **เพิ่มรายการเองในรอบบิล PM ได้** — ปุ่ม "เพิ่มรายการเอง" ในเมนู PM (ต้องเลือกรอบบิลในตัวกรองก่อน) เปิดฟอร์มให้กรอก Description/รหัสสาขา/ชื่อสาขา (ถ้ามี)/ราคา/หมายเหตุ แล้วแนบเข้ารอบบิลที่เลือกได้ทันที ไม่ต้องมาจากระบบ PM — แถวที่เพิ่มเองจะมีพื้นหลังสีเขียวอ่อนในตาราง และมีปุ่มลบ (ลบได้เฉพาะแถวที่เพิ่มเองเท่านั้น ลบแถวจากระบบ PM จริงไม่ได้)
3. **บังคับเลือกช่วงวันที่ก่อนดูตัวอย่าง/บันทึกรอบบิล PM เสมอ** — เดิมเว้นว่างได้ (ดึงงานทั้งหมดที่ยังไม่เคยบันทึก) ตอนนี้ต้องเลือก "วันที่ปิดงาน ตั้งแต่/ถึง" ทั้ง 2 ช่องก่อนเสมอ ไม่งั้นจะไม่แสดงอะไรเลย (ป้องกันดึงข้อมูลมั่วรอบเดือนผิด) — ใช้ `visit_date` (วันที่เข้างาน PM) เป็นตัวกรอง เพราะตรวจสอบข้อมูลจริงในระบบ PM แล้วพบว่าไม่มีฟิลด์ "วันที่ปิด" แยกต่างหากที่เชื่อถือได้ (ฟิลด์ที่ดูคล้ายๆ เช่น `confirmed_at`/`updated_at` เป็นค่าที่ backfill มาพร้อมกันทีเดียวตอนย้ายระบบ ไม่ใช่วันที่ปิดจริงรายตัว) งาน PM 1 ครั้งที่ช่างเข้างานก็ถือว่าปิดงานพร้อมกันในวันนั้นอยู่แล้ว จึงใช้ฟิลด์เดียวกันนี้แทน "วันที่ปิด" ได้ตรงความหมาย
4. **ซ่อนเมนู PM จากผู้รับเหมาทั้งหมด (ทั้งหน้าแอปและฝั่งเซิร์ฟเวอร์):**
   - หน้าแอป: แท็บเมนู "PM" ในแถบด้านซ้ายจะไม่แสดงให้ผู้รับเหมาเห็นเลย (แต่ก่อนแสดงอยู่ ถือเป็นช่องโหว่)
   - เซิร์ฟเวอร์: ฟังก์ชัน `getPmBillingDocuments` และ `getPmBillingRoundOptions` เดิมเช็คแค่ว่าล็อกอินอยู่ ไม่ได้เช็คว่าเป็นแอดมิน (ผู้รับเหมาที่รู้วิธีเรียก API ตรงๆ จะดึงข้อมูลราคา/สาขาในใบเสนอราคา PM ออกไปได้) รอบนี้ปิดช่องโหว่นี้แล้ว เหลือแค่แอดมินเท่านั้นที่เรียกได้

3. **ยืนยันอีกครั้ง: งานที่บันทึกรอบบิลไปแล้วไม่โชว์ซ้ำ** — ของเดิมมีอยู่แล้ว (กันด้วย unique constraint บน `pm_visit_id`) ยังทำงานถูกต้องเหมือนเดิม ไม่กระทบจากการแก้รอบนี้

## นี่คือการเปลี่ยนแปลงรอบก่อนหน้า (v1.0.8) — เมนู "PM": กรองช่วงวันที่ + ดาวน์โหลดใบเสนอราคา PDF

1. **กรองช่วงวันที่เข้างาน** ก่อนดูตัวอย่าง/บันทึกรอบบิล PM — เพิ่มช่อง "ตั้งแต่วันที่ / ถึงวันที่" เหนือปุ่ม "ดูตัวอย่างก่อนบันทึกรอบบิล PM" เว้นว่างทั้งคู่ = ดึงงานที่ยังไม่เคยบันทึกทั้งหมดเหมือนเดิม ถ้าใส่ทั้งสองช่อง จะกรองเฉพาะงานที่ "วันที่เข้างาน" อยู่ในช่วงนั้น (ทั้งฝั่ง preview และฝั่งบันทึกจริงใช้เงื่อนไขเดียวกันเป๊ะ กันเห็นตัวอย่างอย่างแล้วบันทึกได้อีกอย่าง)
2. **งานที่บันทึกรอบบิลไปแล้วไม่โชว์ซ้ำ** — พฤติกรรมนี้มีอยู่แล้วเดิม (กันด้วย unique constraint บน `pm_visit_id` + เช็คจากตาราง `pm_billing_documents` ทุกครั้งที่ดูตัวอย่าง) ยืนยันว่ายังทำงานถูกต้องเหมือนเดิม ไม่ได้แก้อะไรตรงนี้เพิ่ม
3. **ปุ่ม "ดาวน์โหลดใบเสนอราคา (PDF)"** ในเมนู PM — สร้าง PDF ใบเสนอราคาตามหน้าตาไฟล์ Excel ต้นฉบับที่ส่งมา (`CRE-PM-CJ-...xlsx`) ให้ 1 ฉบับต่อ 1 รอบบิลที่เลือกไว้ในตัวกรอง "กรองตามรอบบิล PM":
   - แต่ละแถวรายการ = งาน PM 1 สาขาที่บันทึกในรอบนั้น โดย Description = รหัสสาขา + ชื่อสาขา, Qty คงที่ 1, Unit = "Lot", ราคาต่อหน่วย/จำนวนเงิน ดึงจากช่อง `price` ที่บันทึกไว้ (ถ้ายังไม่กรอกราคาจะโชว์ว่างในบรรทัดนั้น)
   - เลขที่เอกสาร ("เลขที่/No.") ใช้เลขรอบบิล PM ในระบบตรงๆ (รูปแบบ `PM-{เลขรอบบิล}`)
   - สรุปยอด Total Item / VAT 7% / Grand Total + จำนวนเงินเป็นตัวอักษรภาษาไทย คำนวณสดจากราคาที่บันทึกไว้ ณ ตอนกดดาวน์โหลด
   - ต้องเลือกรอบบิลใดรอบหนึ่งในตัวกรองก่อนถึงจะกดดาวน์โหลดได้ (เลือก "งานล่าสุดทั้งหมด" ไม่ได้ เพราะเอกสาร 1 ฉบับต้องผูกกับรอบบิล 1 รอบ)
   - **สิ่งที่ควรตรวจสอบก่อนส่งลูกค้าจริง:** ชื่อผู้ติดต่อ/CC, ที่อยู่, เงื่อนไขชำระเงิน (ตอนนี้ hardcode ตามไฟล์ต้นฉบับ 100% เครดิต 45 วัน) และราคาที่ยังไม่ได้กรอกครบทุกสาขา — ถ้าต้องการปรับให้แก้ไขได้จากหน้าแอปโดยตรง แจ้งเพิ่มได้อีกรอบ

## นี่คือการเปลี่ยนแปลงรอบก่อนหน้า (v1.0.7) — เมนู "PM" ใหม่

เพิ่มเมนู **"PM"** ในแอป สำหรับวางบิลงาน Preventive Maintenance โดยดึงข้อมูลมาจาก **ระบบ PM ซึ่งเป็นแอปคนละตัว คนละโปรเจกต์ Supabase** (`ucxzsfiktqswabxfnojr` ชื่อโปรเจกต์ "SuperDatabase") มาแสดง/วางบิลในฝั่ง CP9X โดยตรง

### สถาปัตยกรรมการเชื่อมข้อมูล
- **ทางเดียว**: ระบบ PM ส่งข้อมูลมาให้ CP9X อ่านเท่านั้น CP9X ไม่เขียนอะไรกลับไปที่ฐานข้อมูล PM เลย
- **เกือบเรียลไทม์**: ทุกครั้งที่กด "ดูตัวอย่างก่อนบันทึกรอบบิล PM" หรือ "ยืนยันบันทึกรอบบิล PM" แอปจะไปดึงข้อมูลสดจากระบบ PM ทันที ไม่มีการพักข้อมูลไว้เป็นรอบ
- ผมได้สร้าง Edge Function ชื่อ **`pm-billing-export`** ไว้ในฝั่งโปรเจกต์ PM แล้ว (deploy เรียบร้อยแล้ว ไม่ต้องทำอะไรเพิ่มฝั่งนั้น) ทำหน้าที่ส่งออกเฉพาะงาน PM ที่ **"เสร็จเรียบร้อย (result = เรียบร้อย) และแอดมินยืนยันแล้ว (admin_confirmed = true)"** เท่านั้น ยืนยันตัวตนด้วย secret key ที่ตั้งไว้ตรงกันทั้ง 2 ฝั่ง (ไม่ใช่ JWT ปกติ เพราะเป็นการเรียกข้ามโปรเจกต์)
- ฝั่ง CP9X (`index.ts`) เพิ่มฟังก์ชัน `fetchPmBillableVisits()` ไปเรียก Edge Function นั้น แล้วมี 2 ขั้นตอนแบบเดียวกับระบบวางบิล CJ:
  - `previewPmBillingCandidates` — ดูตัวอย่าง (อ่านอย่างเดียว)
  - `confirmPmBillingRound` — ยืนยันบันทึกจริง (สร้างรอบบิลใหม่ กันซ้ำด้วย unique constraint บน `pm_visit_id` เหมือนที่ทำกับเลขงาน CJ)
- **แยกเป็นคนละส่วนจากระบบวางบิล CJ โดยสิ้นเชิง** ตามที่ตกลงกันไว้ — ตารางคนละตัว (`pm_billing_documents`) เลขรอบบิลคนละชุด (`next_pm_billing_round_no`) ไม่ปนกับ `billing_documents`/`round_no` เดิมแม้แต่น้อย

### ข้อควรทราบเรื่องราคา
ตรวจสอบข้อมูลจริงในระบบ PM แล้วพบว่า **ช่องราคา (`price`) ในตาราง `pm_schedules` ยังกรอกไว้ไม่ครบ** (มีราคาแค่ 8 จาก 1,532 รายการ ณ ตอนที่ตรวจ) ดังนั้น:
- ตอนดึงมาวางบิล ถ้าระบบ PM มีราคาอยู่แล้วจะดึงมาให้อัตโนมัติ ถ้ายังไม่มีจะโชว์เป็นค่าว่าง
- หลังบันทึกรอบบิลแล้ว **แก้ไขราคาในตาราง PM ของ CP9X ได้ภายหลัง** ผ่านฟังก์ชัน `updatePmBillingRow` (เตรียมไว้ในเซิร์ฟเวอร์แล้ว — ยังไม่ได้ทำหน้าแก้ไขในตารางให้ เพราะสิ่งที่ทำรอบนี้คือดูตัวอย่าง/บันทึก/แสดงรายการ ถ้าต้องการแก้ไขราคาจากหน้าตารางโดยตรงเพิ่มเติม แจ้งได้อีกรอบ)

### หน้าตาเมนูใหม่
- ปุ่ม **"ดูตัวอย่างก่อนบันทึกรอบบิล PM"** — เปิดป๊อปอัปแสดงรายการงาน PM ที่พร้อมวางบิล (สาขา/ผู้รับเหมา/ช่างเข้างาน/รอบ PM/วันที่เข้างาน/ราคา) พร้อมนับจำนวนที่เคยบันทึกไปแล้ว
- ปุ่ม **"ยืนยันบันทึกรอบบิล PM"** ในป๊อปอัป — บันทึกจริง ออกเลขรอบบิลใหม่
- ตารางหลักของเมนู + ตัวกรอง "รอบบิล PM" (ดูย้อนหลังแต่ละรอบได้)

## ถ้ายังไม่ได้ deploy ขั้นตอนนี้ (v1.0.7)

แอปจะยังใช้งานได้ปกติทุกอย่าง เพียงแต่เมนู "PM" จะขึ้น error ทุกปุ่ม (ยังไม่มีตาราง/ฟังก์ชันในเซิร์ฟเวอร์) ส่วนเมนูอื่นทั้งหมดใช้งานได้ตามปกติไม่กระทบกัน — deploy เสร็จเมื่อไหร่ เมนู PM ทำงานทันทีโดยไม่ต้องแตะแอปอีก (แอปเชื่อมกับฟังก์ชันเซิร์ฟเวอร์โดยตรง ไม่ต้อง build ใหม่)

## ถ้ายังไม่ได้ทำครบทั้ง 3 ขั้นของรอบนี้ (v1.0.9)

- ยังไม่ได้รัน SQL (ขั้นที่ 1) แต่ deploy Edge Function ไปแล้ว (ขั้นที่ 2): กดบันทึก Description/ราคาในตารางจะขึ้น error เพราะคอลัมน์ `desc_override` ยังไม่มีในฐานข้อมูล — ต้องรัน SQL ก่อนเสมอ
- deploy ครบขั้น 1+2 แต่ยังไม่ build แอปใหม่ (ขั้นที่ 3): ปุ่มดาวน์โหลด PDF ใช้งานได้ปกติ (มีโลโก้+ลายเซ็นจริงแล้วทันที) แต่ตารางเมนู PM ยังไม่มีช่องให้แก้ไข Description/ราคา (ต้อง build แอปใหม่ก่อน)

## ถ้ายังไม่ได้ทำครบทั้ง 2 ขั้นของรอบก่อนหน้า (v1.0.8)

- ทำแค่ขั้นที่ 1 (deploy Edge Function) แต่ยังไม่ build แอปใหม่: ผู้ใช้จะยังเห็นเมนู PM หน้าตาเดิม ไม่มีตัวกรองวันที่/ปุ่มดาวน์โหลด PDF ให้เห็น แต่ใช้งานปุ่มเดิมได้ปกติไม่พัง (เพราะฟังก์ชันเซิร์ฟเวอร์ใหม่รองรับค่าว่าง/ไม่มี arg เพิ่มได้)
- ทำขั้นที่ 2 (build แอปใหม่) แต่ยังไม่ deploy ขั้นที่ 1: กดตัวกรองวันที่/ปุ่มดาวน์โหลด PDF แล้วจะขึ้น error "ไม่รู้จักฟังก์ชัน" เหมือนเดิม เพราะเซิร์ฟเวอร์ยังเป็นโค้ดเก่า — ต้องทำขั้นที่ 1 ให้เสร็จก่อนเสมอ
