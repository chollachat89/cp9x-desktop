# อัปเดตรอบนี้ (v1.0.44) — ขั้นตอนติดตั้ง

รอบนี้แก้ **ฝั่งเซิร์ฟเวอร์ + ฝั่งหน้าแอป** — ไม่มี SQL ใหม่ ต้อง deploy Edge Function + build แอปใหม่

## นี่คือการเปลี่ยนแปลงอะไรบ้าง (v1.0.44)

**แก้เลขลำดับในตารางวางบิลและเอกสารที่ดาวน์โหลด ให้เรียงถูกต้องและนิ่ง**

อาการเดิม: กดดาวน์โหลดตารางแล้วเลขลำดับสลับมั่ว โดยเฉพาะตอนรวมบิลหลายรอบ หรือแยกดูเป็นรอบ ๆ

**เจอ 3 สาเหตุ:**

1. **ฝั่งผู้รับเหมาไม่เคยถูกนับเลขใหม่เลย** โค้ดเดิมนับเลขใหม่เฉพาะตอนแอดมินดูแบบรวมทุกผู้รับเหมาเท่านั้น ผู้รับเหมาที่ล็อกอินเข้ามาจะได้เลขดิบจากฐานข้อมูล ซึ่ง**เริ่มนับ 1 ใหม่ทุกรอบบิลและทุกผู้รับเหมา** พอดูหลายรอบพร้อมกันเลยเห็นเป็น 1,2,3 แล้ว 1,2 แล้ว 1,2,3 วนไปมา
2. **ตัดรายการเคลมออกแล้วเลขเป็นรู** เช่นเหลือ 1,2,4,5 เพราะแถวที่ 3 เป็นเคลมที่ถูกกรองออกจากเอกสารฝั่งนั้น
3. **แถวที่มีเลขลำดับเท่ากันไม่มีตัวตัดสิน** อะไหล่หลายชิ้นในทรัพย์สินเดียวถูกบันทึกด้วยเลขลำดับเดียวกัน ฐานข้อมูลจึงสลับลำดับได้อิสระ ผลคือดาวน์โหลด 2 ครั้งได้ลำดับไม่เหมือนกัน

**แก้เป็น** นับเลขใหม่ทุกครั้งที่แสดงและทุกครั้งที่ออกเอกสาร ทั้งฝั่งแอดมินและฝั่งผู้รับเหมา ใช้กติกาเดียวกันหมด:

- เรียงด้วย **รอบบิล → ผู้รับเหมา → ลำดับเดิม → เลขงาน → เลขทรัพย์สิน → เวลาที่สร้างแถว** (ใส่ตัวตัดสินท้ายสุดครบ ผลจึงออกมาเหมือนเดิมทุกครั้ง)
- **นับต่อเนื่อง 1 ถึง N ทั้งไฟล์** ไม่รีเซ็ตตามรอบ ไม่มีเลขซ้ำ ไม่มีรู
- **1 เลขงาน = 1 ลำดับ** ไม่ว่าจะมีกี่เลขทรัพย์สินหรือกี่อะไหล่
- ไม่แตะค่าลำดับจริงในฐานข้อมูล แก้แค่ค่าที่แสดงและที่พิมพ์ลงเอกสาร

ใช้กติกาเดียวกันทั้ง **ตารางในแอป · CSV ทุกปุ่ม · PDF ทุกปุ่ม · ใบเขียวรายเลขงาน · PDF รอบบิลย้อนหลัง** เลขลำดับจึงตรงกันหมดทุกที่

## ขั้นตอนติดตั้ง v1.0.44 (2 ขั้น)

1. เข้า https://supabase.com/dashboard/project/hefnjozijflnhdunmewl/functions/app-api → **Edit function** → คัดลอก `index.ts` วางแทนทั้งไฟล์ → **Deploy**
2. Build แอปใหม่ แล้ว push tag `v1.0.44`

**วิธีเช็คว่าได้ผลจริง:** ล็อกอินเป็นผู้รับเหมา ไม่ต้องเลือกรอบบิล (ดูรวมทุกรอบ) แล้วกดดาวน์โหลด CSV → เลขลำดับต้องเป็น 1, 2, 3, 4 ต่อเนื่องไม่ซ้ำไม่ข้าม และเลขงานเดียวกันต้องได้เลขเดียวกันทุกแถว

# อัปเดตรอบก่อนหน้า (v1.0.42) — ขั้นตอนติดตั้ง

รอบนี้มี **SQL ใหม่ 2 ไฟล์ + build แอปใหม่** — ไม่ต้อง deploy Edge Function

## นี่คือการเปลี่ยนแปลงอะไรบ้าง (v1.0.42)

**กรอก "จำนวน" เป็นทศนิยมได้แล้ว (เช่น 1.6 กก. / 0.7 เมตร)**

อะไหล่บางรายการขายเป็น **เมตร** หรือ **กก.** แต่เวลาใช้จริงไม่ลงตัว เช่น เติมน้ำยา 1.6 กก. หรือเดินท่อ 0.7 เมตร ระบบเดิมกรอกทศนิยมไม่ได้ ต้องปัดเป็นจำนวนเต็ม ทำให้คิดเงินคลาดเคลื่อน

**สาเหตุที่เจอ 2 จุด:**

1. ช่องกรอก "จำนวน" ทั้งในหน้าต่างเพิ่มอะไหล่และในตารางวางบิล ตั้งค่า `step` เป็น 1 เบราว์เซอร์จึงปฏิเสธค่าทศนิยมทิ้งตั้งแต่ยังไม่ส่งไปเซิร์ฟเวอร์ — แก้เป็นรับทศนิยมได้ทุกช่องแล้ว (รวมช่องราคาในตารางด้วย)
2. คอลัมน์ `qty` ในฐานข้อมูลอาจเป็นชนิดจำนวนเต็ม ซึ่งจะปัดเศษทิ้งเงียบ ๆ — มีไฟล์ SQL `allow-decimal-qty.sql` ตรวจและแก้ให้ (แก้เฉพาะคอลัมน์ที่ยังเป็นจำนวนเต็ม ถ้าเป็น numeric อยู่แล้วจะข้ามไป)

**หน่วยยังคงเป็น เมตร และ กก. เหมือนเดิมทุกอย่าง** ไม่ได้เปลี่ยนเป็นกรัมหรือเซนติเมตร แค่ให้ใส่จำนวนเป็นเศษส่วนของหน่วยใหญ่ได้ · ราคารวมคำนวณอัตโนมัติเหมือนเดิม เช่น น้ำยา R32 **1.6 กก. × 575 = 920 บาท** หรือ ท่อทองแดง **0.7 เมตร × 800 = 560 บาท**

**อัปเดตข้อมูลอะไหล่ 598 รายการ**

ไฟล์ `update-parts-from-book2.sql` อัปเดตข้อมูลอะไหล่ทั้งชุดจากไฟล์ Excel ล่าสุด — รายการที่มีรหัสอยู่แล้วจะถูกอัปเดตทับ รายการใหม่จะถูกเพิ่มเข้าไป ส่วนรหัสที่มีในระบบแต่ไม่มีในไฟล์จะไม่ถูกแตะและไม่ถูกลบ

## ขั้นตอนติดตั้ง v1.0.42 (3 ขั้น)

1. **รัน SQL `allow-decimal-qty.sql`** — เปิด SQL Editor รันบล็อก A ดูชนิดคอลัมน์ก่อน แล้วรันบล็อก B ถ้ามีคอลัมน์ไหนขึ้นว่า "ต้องแก้"
   (ถ้าข้ามขั้นนี้ กรอก 1.6 ในแอปได้ แต่ฐานข้อมูลจะปัดเป็น 2 เงียบ ๆ)
2. **รัน SQL `update-parts-from-book2.sql`** — รันบล็อก A/B ดูก่อน แล้วค่อยรันบล็อก C (อัปเดต) และ D (เพิ่มใหม่)
3. Build แอปใหม่ แล้ว push tag `v1.0.42`

**วิธีเช็คว่าได้ผลจริง:** เพิ่มอะไหล่ที่ขายเป็น กก. (เช่น P188 น้ำยา R32) แล้วกรอกจำนวน `1.6` → ต้องกรอกได้ และหลังบันทึกราคารวมต้องเป็น 920 ไม่ใช่ 1150 (ซึ่งจะเกิดขึ้นถ้าถูกปัดเป็น 2)

**1. เพิ่ม "ประเภทการเก็บเงิน" ตอนเพิ่มอะไหล่ในตารางวางบิล CM**

แถวที่เป็นเคลมจะขึ้นสีเหลืองในตารางให้เห็นชัด และมีคอลัมน์ "ประเภทเก็บเงิน" เพิ่มในแท็บตารางวางบิลของ Google Sheet ด้วย (แอดมินเห็นคอลัมน์นี้เท่านั้น)

**2. ปุ่มดูดข้อความในเมนูพักงาน รองรับข้อความอีกรูปแบบ**

เดิมรองรับเฉพาะแบบที่ขึ้นต้นด้วยเลขข้อและคั่นค่าด้วย `:` ตอนนี้รองรับแบบ "ใบแจ้งซ่อมบำรุง" ที่ไม่มีเลขข้อและไม่มี `:` ด้วย เช่น

```
เลขที่ใบแจ้งซ่อมบำรุง CM20260817-0177
Service Type งานเครื่องเย็น
รหัส-ชื่อสาขา 0064-โป่งดุสิต
รายละเอียดปัญหาที่พบ* หลอดไฟตู้แช่หน้าปิดดับ
พักงาน เข้าตรวจเช็คพบว่าหลอดไฟเสีย ขออนุมัติเปลี่ยนหลอดไฟใหม่ 2 หลอด
```

บรรทัด "พักงาน ..." จะถูกอ่านเป็นเหตุผลที่พัก และถ้ามีคำว่า "ขออนุมัติ" ระบบจะแยกท่อนหลังไปใส่ช่อง "รายการที่ขออนุมัติ" ให้เอง · ข้อความรูปแบบเดิมยังใช้ได้ตามปกติ

**3. กันงานหลุดรอบวางบิล — เพิ่มช่องติ๊ก "รวมงานตกค้าง"**

ปัญหาเดิม: ระบบใช้ "วันที่เข้าแก้ไข" ตัดสินว่างานอยู่รอบไหน ถ้าเลขงานถูกเปิดไว้นานแล้วเพิ่งมาปิดทีหลัง วันที่เข้าแก้ไขอาจตกอยู่ในรอบที่ตัดบิลไปแล้ว พอถึงรอบใหม่งานนั้นจะอยู่นอกช่วงวันที่ทุกครั้ง = ไม่มีวันถูกดึงมาวางบิลเลย

แก้โดยเพิ่มช่องติ๊ก **"รวมงานตกค้าง"** ข้างช่องเลือกช่วงวันที่ ติ๊กแล้วระบบจะไม่สนใจวันเริ่มต้น ดึงทุกงานที่ปิดแล้วจนถึงวันสิ้นสุดรอบมาพิจารณาแทน (งานที่เคยออกบิลไปแล้วยังถูกกันซ้ำเหมือนเดิม ไม่มีทางออกบิลซ้ำ)

**4. บังคับกรอกให้ครบทุกช่องก่อนบันทึกเปิดงาน/ปิดงาน**

เดิมบังคับแค่ 4 ช่อง ทำให้บันทึกทั้งที่ข้อมูลไม่ครบได้ แล้วไปโผล่เป็นช่องว่างในตารางวางบิลและใบเขียวทีหลัง ซึ่งตามแก้ย้อนหลังยากมาก

ตอนนี้ตรวจครบทุกช่องทั้งฝั่งแอปและฝั่งเซิร์ฟเวอร์ ถ้าขาดช่องไหนจะบอกชื่อช่องนั้นตรง ๆ แล้วเลื่อนจอไปที่ช่องให้เลย · **เลขทรัพย์สินบังคับ 12 หลักเสมอ** ปล่อยว่างไม่ได้อีกต่อไป (เพราะระบบใช้คู่ เลขงาน+เลขทรัพย์สิน เป็นตัวกันปิดงานซ้ำ ถ้าปล่อยว่างจะกันซ้ำไม่ได้จริง)

1. **ช่องกรอกในฟอร์มเปิดงาน** — อยู่ถัดจากช่อง "งานบริการ"
2. **ปุ่มดูดข้อความอ่านให้อัตโนมัติ** — รองรับทั้งแบบที่หัวข้อกับค่าอยู่คนละบรรทัด (แบบที่ใช้จริง) และแบบใส่ `:` บรรทัดเดียว
3. **ตารางตรวจสอบเปิดงาน** — เพิ่มคอลัมน์ Service Issue
4. **แท็บ "เปิดงาน" ใน Google Sheet** — เพิ่มคอลัมน์ Service Issue
5. **หน้ารายงานสถานะดำเนินการ** — เพิ่มคอลัมน์ในตาราง (ซ่อน/แสดงได้จากปุ่มจัดการคอลัมน์), เพิ่มบรรทัดในหน้า "ดูรายละเอียด" และเพิ่มคอลัมน์ในไฟล์ CSV ที่ดาวน์โหลดจากหน้านั้น
6. **แท็บ "รายงานสถานะดำเนินการ" ใน Google Sheet** — เพิ่มคอลัมน์ Service Issue
7. **VIEW `status_report_view` ใน Supabase** — เพิ่มคอลัมน์ "Service Issue" พร้อมตัวอย่าง query สรุปว่าอาการเสียแบบไหนเจอบ่อยที่สุด

**แก้บั๊กสำคัญ: หัวตารางกับข้อมูลเหลื่อมกันคนละช่อง** — อาการคือแบดจ์สถานะไปโผล่ใต้หัวคอลัมน์ "เลขทรัพย์สิน" และปุ่มดูรายละเอียดไปอยู่ใต้หัว "สถานะ"

สาเหตุ: ตารางวางบิลกับตารางรายงานสถานะใช้ชื่อคอลัมน์ซ้ำกัน 3 ตัว (`asset_id`, `contractor`, `service_type`) แต่ปุ่มซ่อน/แสดงคอลัมน์เลือกอิลิเมนต์แบบทั้งหน้าจอ พอซ่อนคอลัมน์ในตารางหนึ่ง มันไปซ่อน**หัวตาราง**ของอีกตารางหนึ่งด้วย ข้อมูลในตารางนั้นเลยเลื่อนไปคนละช่องกับหัว — แก้โดยจำกัดขอบเขตให้แต่ละตารางแตะเฉพาะคอลัมน์ของตัวเอง

**ปรับหน้าตาให้ดูเป็นทางการและอ่านง่ายขึ้น**

- **แบดจ์สถานะ** เปลี่ยนจากพิลล์สีจัด เป็นจุดสีนำหน้า + พื้นอ่อน ขอบบาง ตัวเล็กลง ไม่แย่งสายตาจากข้อมูลจริงเวลามีหลายแถวเรียงกัน
- **แถวในตาราง** เตี้ยลง เห็นข้อมูลได้มากขึ้นต่อหน้าจอ พร้อมไฮไลท์แถวตอนเอาเมาส์ชี้ กวาดตาตามแถวยาว ๆ ไม่หลุด
- **หัวตาราง** ตรึงไว้ด้านบน เลื่อนดูข้อมูลยาว ๆ แล้วยังเห็นว่าคอลัมน์ไหนคืออะไร สีอ่อนลงและตัวเล็กลงให้เป็นพื้นหลัง ไม่เด่นกว่าข้อมูล
- **เลขงาน/เลขทรัพย์สิน/วันที่** ใช้ตัวเลขความกว้างคงที่ เรียงกันเป็นแนวตรง อ่านเทียบกันง่าย
- **ช่องที่ยังไม่มีข้อมูล** ขึ้นขีดจาง ๆ แทนช่องว่างเปล่า จะได้แยกออกว่า "ยังไม่มีข้อมูล" ไม่ใช่ "ระบบไม่แสดง"
- **หน้าดูรายละเอียด** ป้ายกำกับกว้างเท่ากันทุกแถว ค่าชิดซ้ายตรงกัน อ่านไล่ลงมาเป็นแนวเดียว แถวกระชับขึ้นเห็นได้ครบในจอเดียว

รูปแบบข้อความที่ดูดได้ (หัวข้อบรรทัดหนึ่ง ค่าบรรทัดถัดไป ไม่ต้องมีเครื่องหมาย `:`) :

```
Service Issue
F04_ไม่เย็น/อุณหภูมิไม่ได้มาตรฐาน
```

> ข้อความเปิดงานเดิมที่ไม่มีบรรทัด Service Issue ยังดูดได้ตามปกติ ช่องนี้จะเว้นว่างไว้ให้กรอกเอง

# เพิ่มเติม (ไม่ผูกกับเวอร์ชันแอป) — VIEW รายงานสถานะใน Supabase

เพิ่มไฟล์ `status-report-view.sql` — สร้าง VIEW ชื่อ `status_report_view` ใน Supabase รวมข้อมูลสถานะทุกเลขงานไว้ที่เดียวแบบละเอียดที่สุด (ตรรกะสถานะตรงกับหน้า "รายงานสถานะดำเนินการ" ในแอปทุกประการ รวมเลขงานที่ปิดงานหลายครั้งด้วย)

รวมข้อมูลจาก 4 ตาราง (`open_issues` + `close_issues` + `billing_documents` + `pause_records`) ชื่อคอลัมน์เป็นภาษาไทยอ่านง่าย ครอบคลุม:

- **ฝั่งเปิดงาน:** เลขที่ใบแจ้งซ่อมบำรุง, สาขา, รหัส/ชื่อสาขา, Service Type, **งานบริการ (รหัส F ต่าง ๆ)**, ประเภทสัญญา, ผู้รับเหมา, รายละเอียดปัญหา, วันที่ร้องขอ/เปิดงาน
- **ฝั่งปิดงาน:** เลขทรัพย์สิน, วันที่เข้าแก้ไข, วันที่ปิดงาน, ดำเนินการแก้ไขแล้ว, รายการอะไหล่ที่เปลี่ยน, ลิงก์แนบรูป, จำนวนครั้งที่ปิดงานของเลขงานนั้น
- **ระยะเวลา:** ระยะเวลาดำเนินการ ทั้งหน่วยชั่วโมงและวัน
- **พักงาน:** จำนวนครั้งที่พัก, รวมชั่วโมงที่พัก, กำลังพักอยู่หรือไม่, วันเวลาพักครั้งแรก/ล่าสุด, เหตุผล/หมายเหตุ/ผู้ทำรายการของการพักครั้งล่าสุด
- **วางบิล:** ส่งมอบงานแล้วหรือยัง, ตัดบิลแล้วหรือยัง, วันที่ตัดบิล, รอบบิลที่, ช่วงรอบบิล, Quotation, จำนวนรายการในบิล, ยอดรวมทั้งฝั่ง CJ และผู้รับเหมา, รายการอะไหล่ในบิล, ผู้รับผิดชอบ, บริษัท
- **สถานะสรุป**

ในไฟล์มีตัวอย่าง query สำเร็จรูปแถมให้ด้วย เช่น สรุปยอดตามสถานะ, สรุปตามงานบริการ (รหัส F), งานที่ยังค้างเรียงตามอายุงาน, ระยะเวลาดำเนินการเฉลี่ยแยกตามงานบริการ

เป็น VIEW ไม่ใช่ตารางจริง จึงไม่ต้องซิงค์ ข้อมูลสดใหม่เสมอ เปิดดูได้ทันทีจาก Supabase Dashboard -> Table Editor -> `status_report_view`

**วิธีติดตั้ง:** เปิด Supabase Dashboard ของโปรเจกต์ CP9X -> SQL Editor -> New query -> วางโค้ดทั้งหมดใน `status-report-view.sql` -> กด Run (รันซ้ำได้อย่างปลอดภัย)

## นี่คือการเปลี่ยนแปลงอะไรบ้าง (v1.0.30)

**เพิ่ม "งานบริการ" (รหัส F ต่าง ๆ) เข้าไปในรายงานสถานะดำเนินการ** — เดิมข้อมูลช่องนี้มีอยู่ในระบบตั้งแต่ตอนเปิดงานแล้ว แต่ไม่เคยถูกดึงมาแสดงในรายงานสถานะเลย รอบนี้เพิ่มให้ครบทั้ง 4 จุดพร้อมกัน:

1. **หน้าต่าง "ดูรายละเอียด"** — เพิ่มบรรทัด "งานบริการ" ต่อจาก Service Type (ตามที่แจ้ง)
2. **ตารางรายงานสถานะ** — เพิ่มคอลัมน์ "งานบริการ" (ซ่อน/แสดงได้จากปุ่มจัดการคอลัมน์เหมือนคอลัมน์อื่น)
3. **ไฟล์ CSV ที่ดาวน์โหลดจากหน้ารายละเอียด** — เพิ่มคอลัมน์ "งานบริการ"
4. **แท็บ "รายงานสถานะดำเนินการ" ใน Google Sheet** — เพิ่มคอลัมน์ "งานบริการ"

**แก้ระบบซิงค์ Google Sheet ให้ข้อมูลตรงเสมอเมื่อคอลัมน์เปลี่ยน (สำคัญ)** — เดิมระบบเขียนหัวตารางแค่ตอน "สร้างแท็บใหม่" เท่านั้น แท็บที่มีอยู่แล้วจะใช้หัวตารางชุดเดิมตลอดไป พอมีการเพิ่ม/ลด/สลับคอลัมน์ (อย่างการเพิ่ม "งานบริการ" รอบนี้) จะเกิดปัญหา 2 อย่างพร้อมกัน:

1. ตำแหน่งคอลัมน์ "รหัสอ้างอิง" ขยับไป 1 ช่อง → ระบบอ่านรหัสอ้างอิงไม่เจอสักแถว → คิดว่าทุกแถวเป็นข้อมูลใหม่ แล้วเพิ่มซ้ำเข้าไปทั้งหมดอีกชุด (ข้อมูลบานเป็น 2 เท่า)
2. แถวเก่าที่เขียนตามคอลัมน์ชุดเดิม จะเหลื่อมกับหัวตารางชุดใหม่ → ข้อมูลอยู่ผิดคอลัมน์ทั้งตาราง

แก้ให้ตอนนี้ระบบ **ตรวจหัวตารางในชีตทุกครั้งก่อนซิงค์** ถ้าพบว่าไม่ตรงกับชุดคอลัมน์ปัจจุบัน จะสร้างตารางใหม่ให้อัตโนมัติ 3 ขั้น:

1. ล้างค่าเดิมทั้งแท็บ

## นี่คือการเปลี่ยนแปลงอะไรบ้าง (v1.0.19)

**เปลี่ยนวิธีซิงค์ข้อมูลไป Google Sheet จาก "ลบของเก่าทั้งหมดแล้วเขียนใหม่ทุกครั้ง" เป็น "เติมเฉพาะแถวใหม่ที่ยังไม่เคยส่ง + อัปเดตแถวเดิมที่เคยส่งแล้วถ้ามีการแก้ไข"**

ของเดิมทุกครั้งที่กด "ซิงค์ข้อมูล" ระบบจะลบข้อมูลทั้งหมดในทุกแท็บของ Google Sheet แล้วดึงข้อมูลจาก Supabase มาเขียนทับใหม่หมด (จำกัดแค่ 5,000 แถวล่าสุดต่อตารางด้วย ถ้าตารางไหนมีมากกว่านั้นข้อมูลเก่าจะหายไปจาก Sheet) รอบนี้เปลี่ยนเป็น:

1. สร้างตารางใหม่ `sheet_sync_state` เก็บว่าแต่ละแถวข้อมูล (อ้างอิงด้วย `id` ของแถวในฐานข้อมูล) เคยถูกส่งไปอยู่ที่แถวไหนในแท็บไหนของ Sheet แล้วบ้าง
2. ตอนซิงค์: แถวไหนยังไม่เคยส่ง (ไม่มีสถานะบันทึกไว้) = เพิ่มต่อท้ายแท็บนั้น แล้วจำตำแหน่งไว้ ไม่ซ้ำแน่นอน
3. แถวไหนเคยส่งไปแล้ว = เขียนทับข้อมูลปัจจุบันลงตำแหน่งเดิมโดยตรง (ถ้ามีการแก้ไขข้อมูลในแอปภายหลัง เช่น แก้ราคาบิล จะอัปเดตตามให้ทุกครั้งที่ซิงค์ ไม่ใช่แค่ส่งครั้งเดียวจบ)
4. ไม่มีลิมิต 5,000 แถวเหมือนเดิมอีกต่อไป (ต่อรอบซิงค์ตรวจได้ถึง 20,000 แถว ถ้ามากกว่านั้นแถวเก่าสุดจะรออัปเดตในรอบถัดไป แต่จะไม่หายไปจาก Sheet เหมือนของเดิม)

**ข้อควรทราบ (ต่างจากของเดิม):** ถ้ามีการ "ลบ" ข้อมูลออกจากฐานข้อมูลจริง ๆ (เช่น ลบเลขงานที่กรอกผิด) แถวนั้นจะ **ไม่หายไปจาก Google Sheet เองอัตโนมัติ** เหมือนของเดิมอีกต่อไป (ของเดิมลบ-เขียนใหม่ทุกรอบเลยล้างแถวเก่าให้เองด้วย) ถ้าต้องการลบแถวที่ถูกลบใน Supabase ออกจาก Sheet ต้องไปลบเองในชีต

**สำคัญมาก - ต้องทำก่อนใช้งานครั้งแรก:** ไปลบข้อมูลแถวเก่าทั้งหมดในทุกแท็บของ Google Sheet ปลายทางออกก่อน (เว้นแถวหัวตารางแถวที่ 1 ไว้) เพราะรอบซิงค์แรกหลังอัปเดตนี้จะมองว่าทุกแถวเป็นข้อมูลใหม่ทั้งหมด (ยังไม่มีสถานะบันทึกไว้ใน `sheet_sync_state`) แล้วเพิ่มต่อท้ายข้อมูลเดิมที่ยังค้างอยู่ ทำให้ซ้ำกันได้ถ้าไม่ล้างก่อน

ส่วนคอลัมน์ "รายละเอียด" ในเมนู "รายงานสถานะดำเนินการ" (รายละเอียดปัญหาที่พบของแต่ละเลขงาน) มีอยู่ในแท็บ "รายงานสถานะดำเนินการ" ของ Sheet อยู่แล้วตั้งแต่เดิม รอบนี้ตรวจสอบซ้ำแล้วว่ายังคงซิงค์ไปด้วยตามปกติ

สาเหตุ: ระบบจับคู่/จองคิวสร้างบิล เดิมออกแบบมาแบบ "1 เลขงาน = วางบิลได้แค่ครั้งเดียวตลอดไป" (เช็คแค่ว่าเลขงานนี้เคยมีบิลรอบไหนมาก่อนหรือยัง ไม่ได้แยกตามเลขทรัพย์สิน) พอเลขงานหนึ่งมีบิลจากการปิดงานครั้งแรกไปแล้ว การปิดงานครั้งถัดไป (เลขทรัพย์สินอื่น) จะถูกมองว่า "เลขงานนี้บิลไปแล้ว" และไม่ถูกจับคู่มาสร้างบิลอีกเลย

แก้โดยเปลี่ยนการเช็ค/จองคิวจากระดับ "เลขงาน" เป็นระดับ "เลขงาน + เลขทรัพย์สิน" คู่เดียวกัน (เหมือนที่แก้ฝั่งปิดงานไปแล้วใน v1.0.17) — เลขงานเดิมที่มีการปิดงานเพิ่มเติมคนละเลขทรัพย์สิน จะถูกจับคู่มาสร้างบิลเป็นแถวใหม่แยกต่างหากได้ถูกต้อง ไม่ถูกมองว่า "บิลไปแล้ว" อีกต่อไป (ทำโดยไม่แตะต้องระบบจองคิวกันชนกันเดิมโดยตรง เพื่อความปลอดภัย ลดความเสี่ยงกับข้อมูลบิลจริง)

## นี่คือการเปลี่ยนแปลงอะไรบ้าง (v1.0.17)

**1 เลขงาน ปิดงานได้มากกว่า 1 ครั้งแล้ว** (เดิมระบบห้ามปิดซ้ำเด็ดขาดถ้าเลขงานเดียวกัน แต่ในความเป็นจริง 1 ใบแจ้งซ่อมอาจมีทรัพย์สินหลายชิ้นที่ต้องปิดงานแยกกัน ใช้แบบฟอร์มเดียวกันแต่กรอกคนละ "เลขทรัพย์สิน")

1. เปลี่ยนกฎกันกรอกซ้ำจาก **"ห้ามซ้ำเลขงาน"** เป็น **"ห้ามซ้ำเฉพาะเลขงาน + เลขทรัพย์สิน คู่เดียวกัน"** — เลขงานเดียวกันแต่เลขทรัพย์สินคนละชิ้น บันทึกปิดงานเพิ่มได้เรื่อย ๆ ไม่จำกัดจำนวนครั้ง (เหมือนกดปุ่ม "เพิ่มอะไหล่" ไม่ต้องมีลำดับ/เลขกำกับเพิ่ม) ส่วนเลขงาน+เลขทรัพย์สินชิ้นเดิม (หรือไม่กรอกเลขทรัพย์สินทั้งคู่) ยังกันซ้ำเหมือนเดิม
2. ปรับทั้งจุดเช็คสด (ตอนพิมพ์เลขงาน/เลขทรัพย์สินในฟอร์ม), จุดเช็คก่อนกดบันทึกจริง, และจุดกันซ้ำระดับฐานข้อมูล (unique index) ให้ตรงกันหมดทั้ง 3 ชั้น
3. **แก้บั๊กที่พบระหว่างทาง:** ตอนจับคู่ข้อมูล "เลขงานไหนอยู่ในช่วงวันที่ที่เลือก" สำหรับสร้างรอบบิล เดิมเช็คแค่ "ปิดงานครั้งแรก" ของแต่ละเลขงานเท่านั้น ถ้าเลขงานมีปิดงานหลายครั้งและครั้งแรกอยู่นอกช่วงวันที่ (แต่ครั้งหลังอยู่ในช่วง) จะตกหล่นไม่ถูกจับคู่ — แก้ให้เช็คทุกครั้งที่ปิดงานของเลขงานนั้นแล้ว
4. **ตารางวางบิลไม่ต้องแก้อะไรเพิ่ม** — ระบบเดิมมีปุ่ม "เพิ่มอะไหล่อีกชิ้น" ในหน้าต่างแก้ไขตารางวางบิลอยู่แล้ว ซึ่งรองรับหลายแถวต่อ 1 เลขงานอยู่แล้วในตัว (ใช้กลไกเดียวกันได้เลยถ้าต้องเพิ่มแถวสำหรับทรัพย์สินชิ้นอื่น)

## นี่คือการเปลี่ยนแปลงรอบก่อนหน้า (v1.0.8) — เมนู "PM": กรองช่วงวันที่ + ดาวน์โหลดใบเสนอราคา PDF

1. **กรองช่วงวันที่เข้างาน** ก่อนดูตัวอย่าง/บันทึกรอบบิล PM — เพิ่มช่อง "ตั้งแต่วันที่ / ถึงวันที่" เหนือปุ่ม "ดูตัวอย่างก่อนบันทึกรอบบิล PM" เว้นว่างทั้งคู่ = ดึงงานที่ยังไม่เคยบันทึกทั้งหมดเหมือนเดิม ถ้าใส่ทั้งสองช่อง จะกรองเฉพาะงานที่ "วันที่เข้างาน" อยู่ในช่วงนั้น (ทั้งฝั่ง preview และฝั่งบันทึกจริงใช้เงื่อนไขเดียวกันเป๊ะ กันเห็นตัวอย่างอย่างแล้วบันทึกได้อีกอย่าง)
2. **งานที่บันทึกรอบบิลไปแล้วไม่โชว์ซ้ำ** — พฤติกรรมนี้มีอยู่แล้วเดิม (กันด้วย unique constraint บน `pm_visit_id` + เช็คจากตาราง `pm_billing_documents` ทุกครั้งที่ดูตัวอย่าง) ยืนยันว่ายังทำงานถูกต้องเหมือนเดิม ไม่ได้แก้อะไรตรงนี้เพิ่ม
3. **ปุ่ม "ดาวน์โหลดใบเสนอราคา (PDF)"** ในเมนู PM — สร้าง PDF ใบเสนอราคาตามหน้าตาไฟล์ Excel ต้นฉบับที่ส่งมา (`CRE-PM-CJ-...xlsx`) ให้ 1 ฉบับต่อ 1 รอบบิลที่เลือกไว้ในตัวกรอง "กรองตามรอบบิล PM":
   - แต่ละแถวรายการ = งาน PM 1 สาขาที่บันทึกในรอบนั้น โดย Description = รหัสสาขา + ชื่อสาขา, Qty คงที่ 1, Unit = "Lot", ราคาต่อหน่วย/จำนวนเงิน ดึงจากช่อง `price` ที่บันทึกไว้ (ถ้ายังไม่กรอกราคาจะโชว์ว่างในบรรทัดนั้น)
   - เลขที่เอกสาร ("เลขที่/No.") ใช้เลขรอบบิล PM ในระบบตรงๆ (รูปแบบ `PM-{เลขรอบบิล}`)
   - สรุปยอด Total Item / VAT 7% / Grand Total + จำนวนเงินเป็นตัวอักษรภาษาไทย คำนวณสดจากราคาที่บันทึกไว้ ณ ตอนกดดาวน์โหลด
   - ต้องเลือกรอบบิลใดรอบหนึ่งในตัวกรองก่อนถึงจะกดดาวน์โหลดได้ (เลือก "งานล่าสุดทั้งหมด" ไม่ได้ เพราะเอกสาร 1 ฉบับต้องผูกกับรอบบิล 1 รอบ)
   - **สิ่งที่ควรตรวจสอบก่อนส่งลูกค้าจริง:** ชื่อผู้ติดต่อ/CC, ที่อยู่, เงื่อนไขชำระเงิน (ตอนนี้ hardcode ตามไฟล์ต้นฉบับ 100% เครดิต 45 วัน) และราคาที่ยังไม่ได้กรอกครบทุกสาขา — ถ้าต้องการปรับให้แก้ไขได้จากหน้าแอปโดยตรง แจ้งเพิ่มได้อีกรอบ

## นี่คือการเปลี่ยนแปลงรอบก่อนหน้า (v1.0.7) — เมนู "PM" ใหม่

เพิ่มเมนู **"PM"** ในแอป สำหรับวางบิลงาน Preventive Maintenance โดยดึงข้อมูลมาจาก **ระบบ PM ซึ่งเป็นแอปคนละตัว คนละโปรเจกต์ Supabase** (`ucxzsfiktqswabxfnojr` ชื่อโปรเจกต์ "SuperDatabase") มาแสดง/วางบิลในฝั่ง CP9X โดยตรง

### สถาปัตยกรรมการเชื่อมข้อมูล
- **ทางเดียว**: ระบบ PM ส่งข้อมูลมาให้ CP9X อ่านเท่านั้น CP9X ไม่เขียนอะไรกลับไปที่ฐานข้อมูล PM เลย
- **เกือบเรียลไทม์**: ทุกครั้งที่กด "ดูตัวอย่างก่อนบันทึกรอบบิล PM" หรือ "ยืนยันบันทึกรอบบิล PM" แอปจะไปดึงข้อมูลสดจากระบบ PM ทันที ไม่มีการพักข้อมูลไว้เป็นรอบ
- ผมได้สร้าง Edge Function ชื่อ **`pm-billing-export`** ไว้ในฝั่งโปรเจกต์ PM แล้ว (deploy เรียบร้อยแล้ว ไม่ต้องทำอะไรเพิ่มฝั่งนั้น) ทำหน้าที่ส่งออกเฉพาะงาน PM ที่ **"เสร็จเรียบร้อย (result = เรียบร้อย) และแอดมินยืนยันแล้ว (admin_confirmed = true)"** เท่านั้น ยืนยันตัวตนด้วย secret key ที่ตั้งไว้ตรงกันทั้ง 2 ฝั่ง (ไม่ใช่ JWT ปกติ เพราะเป็นการเรียกข้ามโปรเจกต์)
- ฝั่ง CP9X (`index.ts`) เพิ่มฟังก์ชัน `fetchPmBillableVisits()` ไปเรียก Edge Function นั้น แล้วมี 2 ขั้นตอนแบบเดียวกับระบบวางบิล CJ:
  - `previewPmBillingCandidates` — ดูตัวอย่าง (อ่านอย่างเดียว)
  - `confirmPmBillingRound` — ยืนยันบันทึกจริง (สร้างรอบบิลใหม่ กันซ้ำด้วย unique constraint บน `pm_visit_id` เหมือนที่ทำกับเลขงาน CJ)
- **แยกเป็นคนละส่วนจากระบบวางบิล CJ โดยสิ้นเชิง** ตามที่ตกลงกันไว้ — ตารางคนละตัว (`pm_billing_documents`) เลขรอบบิลคนละชุด (`next_pm_billing_round_no`) ไม่ปนกับ `billing_documents`/`round_no` เดิมแม้แต่น้อย

### ข้อควรทราบเรื่องราคา
ตรวจสอบข้อมูลจริงในระบบ PM แล้วพบว่า **ช่องราคา (`price`) ในตาราง `pm_schedules` ยังกรอกไว้ไม่ครบ** (มีราคาแค่ 8 จาก 1,532 รายการ ณ ตอนที่ตรวจ) ดังนั้น:
- ตอนดึงมาวางบิล ถ้าระบบ PM มีราคาอยู่แล้วจะดึงมาให้อัตโนมัติ ถ้ายังไม่มีจะโชว์เป็นค่าว่าง
- หลังบันทึกรอบบิลแล้ว **แก้ไขราคาในตาราง PM ของ CP9X ได้ภายหลัง** ผ่านฟังก์ชัน `updatePmBillingRow` (เตรียมไว้ในเซิร์ฟเวอร์แล้ว — ยังไม่ได้ทำหน้าแก้ไขในตารางให้ เพราะสิ่งที่ทำรอบนี้คือดูตัวอย่าง/บันทึก/แสดงรายการ ถ้าต้องการแก้ไขราคาจากหน้าตารางโดยตรงเพิ่มเติม แจ้งได้อีกรอบ)

### หน้าตาเมนูใหม่
- ปุ่ม **"ดูตัวอย่างก่อนบันทึกรอบบิล PM"** — เปิดป๊อปอัปแสดงรายการงาน PM ที่พร้อมวางบิล (สาขา/ผู้รับเหมา/ช่างเข้างาน/รอบ PM/วันที่เข้างาน/ราคา) พร้อมนับจำนวนที่เคยบันทึกไปแล้ว
- ปุ่ม **"ยืนยันบันทึกรอบบิล PM"** ในป๊อปอัป — บันทึกจริง ออกเลขรอบบิลใหม่
- ตารางหลักของเมนู + ตัวกรอง "รอบบิล PM" (ดูย้อนหลังแต่ละรอบได้)

## ถ้ายังไม่ได้ deploy ขั้นตอนนี้ (v1.0.7)

แอปจะยังใช้งานได้ปกติทุกอย่าง เพียงแต่เมนู "PM" จะขึ้น error ทุกปุ่ม (ยังไม่มีตาราง/ฟังก์ชันในเซิร์ฟเวอร์) ส่วนเมนูอื่นทั้งหมดใช้งานได้ตามปกติไม่กระทบกัน — deploy เสร็จเมื่อไหร่ เมนู PM ทำงานทันทีโดยไม่ต้องแตะแอปอีก (แอปเชื่อมกับฟังก์ชันเซิร์ฟเวอร์โดยตรง ไม่ต้อง build ใหม่)

## ถ้ายังไม่ได้ทำครบทั้ง 3 ขั้นของรอบนี้ (v1.0.9)

- ยังไม่ได้รัน SQL (ขั้นที่ 1) แต่ deploy Edge Function ไปแล้ว (ขั้นที่ 2): กดบันทึก Description/ราคาในตารางจะขึ้น error เพราะคอลัมน์ `desc_override` ยังไม่มีในฐานข้อมูล — ต้องรัน SQL ก่อนเสมอ
- deploy ครบขั้น 1+2 แต่ยังไม่ build แอปใหม่ (ขั้นที่ 3): ปุ่มดาวน์โหลด PDF ใช้งานได้ปกติ (มีโลโก้+ลายเซ็นจริงแล้วทันที) แต่ตารางเมนู PM ยังไม่มีช่องให้แก้ไข Description/ราคา (ต้อง build แอปใหม่ก่อน)

## ถ้ายังไม่ได้ทำครบทั้ง 2 ขั้นของรอบก่อนหน้า (v1.0.8)

- ทำแค่ขั้นที่ 1 (deploy Edge Function) แต่ยังไม่ build แอปใหม่: ผู้ใช้จะยังเห็นเมนู PM หน้าตาเดิม ไม่มีตัวกรองวันที่/ปุ่มดาวน์โหลด PDF ให้เห็น แต่ใช้งานปุ่มเดิมได้ปกติไม่พัง (เพราะฟังก์ชันเซิร์ฟเวอร์ใหม่รองรับค่าว่าง/ไม่มี arg เพิ่มได้)
- ทำขั้นที่ 2 (build แอปใหม่) แต่ยังไม่ deploy ขั้นที่ 1: กดตัวกรองวันที่/ปุ่มดาวน์โหลด PDF แล้วจะขึ้น error "ไม่รู้จักฟังก์ชัน" เหมือนเดิม เพราะเซิร์ฟเวอร์ยังเป็นโค้ดเก่า — ต้องทำขั้นที่ 1 ให้เสร็จก่อนเสมอ
